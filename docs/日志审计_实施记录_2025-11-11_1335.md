# 日志审计模块实施记录（节点三，2025-11-11 13:35）

本节点在“节点二”基础上，完善成功兜底（可选开关）、导出内存优化与可观测性指标。

增量内容
- 成功兜底（AOP，可配置）
  - 位置：backend/src/main/java/com/filemanager/audit/ApiAuditAspect.java
  - 开关：application.yml `audit.success-fallback.enabled`（默认 false），`audit.success-fallback.only-get`（默认 true）
  - 行为：当开启时，对控制器成功返回的请求记录 `API_{METHOD}` 成功日志（仅GET可选），避免漏记（显式埋点仍为主）
- 导出优化（XLSX流式）
  - Controller 改用 `SXSSFWorkbook(100)` 流式写出，降低内存占用
  - 位置：backend/src/main/java/com/filemanager/controller/AdminLogController.java
- 可观测性指标
  - 新增指标服务：backend/src/main/java/com/filemanager/metrics/AuditMetricsService.java
  - 计数：`audit.logs.success`、`audit.logs.failed`、`audit.purge.deleted`
  - 挂载：AuditLogService 写入成功/失败时累加；AuditLogPurgeScheduler 清理完成后累加删除条数
- 配置
  - application.yml 增加：
    - `audit.success-fallback.enabled: false`
    - `audit.success-fallback.only-get: true`

验证建议
- 开启成功兜底：将 `audit.success-fallback.enabled` 设为 true，访问一些仅GET的接口，校验“API调用成功”日志；再关闭开关，避免重复噪音
- 导出：大数据行数（接近上限）导出 XLSX 时内存占用稳定
- 指标：访问 `/actuator/metrics/audit.logs.success` 等查看指标增长

备注
- 成功兜底默认关闭，推荐以服务层显式埋点为主，避免重复记录
- 后续可选：将“用户名不存在”的登录失败纳入系统级日志（需要允许无 user_id 的记录或独立表）
