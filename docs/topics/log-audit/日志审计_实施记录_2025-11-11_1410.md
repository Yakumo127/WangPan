# 日志审计模块实施记录（节点五，2025-11-11 14:10）

本节点完成“第1点 + 第2点”：
1) 管理员到期清理（定时任务）增加系统级审计日志
2) “用户名不存在”的登录失败纳入系统级日志

变更摘要
- System用户
  - DataInitializer：创建内置 `system` 账户（禁用/锁定，仅用于审计归属）
- 审计写入服务增强
  - AuditLogService：新增 `logSystemSuccess/logSystemFailure`，在 `userId==null` 时回退到 `system`（不存在则回退 admin）
- 定时任务审计
  - AuditLogPurgeScheduler：清理完成后记录 `ADMIN_PURGE_EXPIRED` 成功日志（resourceType=SYSTEM，resourceName=audit.purge，描述含删除条数与保留期）
- 登录失败（用户不存在）
  - UserService.login/adminLogin：在用户不存在场景记录系统级失败日志（动作=LOGIN，资源=USER，resourceName=输入的用户名）
- 动作与字典
  - UserLog 常量补齐（RESTORE/ADMIN_* 与回收站动作已在上一节点完成）
  - 字典接口 `/api/admin/logs/actions` 中 `resourceTypes` 增加 `SYSTEM`

验证建议
- 造出过期 `user_logs`，等待定时或手动触发任务后，查看“系统级”日志：`ADMIN_PURGE_EXPIRED`（resourceType=SYSTEM）
- 使用不存在的用户名请求登录/管理员登录，查看系统级失败日志，resourceName 为尝试的用户名

备注
- 未变更 `user_logs.user_id` 非空约束，通过“system”账户作为归属避免DDL变更
- 若未来需要完全独立的系统日志表，可在后续新增表结构与迁移
