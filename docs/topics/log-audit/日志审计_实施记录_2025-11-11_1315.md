# 日志审计模块实施记录（节点二，2025-11-11 13:15）

本节点在“节点一”的基础上，补齐导出、定时清理与控制器异常兜底，为“所有操作可审计”提供更完整保障。

增量内容
- 导出能力（管理员）
  - 路由：GET `/api/admin/logs/export`
  - 参数：与分页查询一致，新增 `format=csv|xlsx`、`maxRows`（默认≤50000）
  - 实现：
    - 控制器：backend/src/main/java/com/filemanager/controller/AdminLogController.java（新增方法，内置 CSV/XLSX 生成）
    - 查询：queryService.queryAllLimited（同过滤条件，限制行数）
- 定时清理（保留期）
  - 任务：backend/src/main/java/com/filemanager/task/AuditLogPurgeScheduler.java
  - 配置：`audit.retention-days: 180`，`audit.purge.cron: 0 0 3 * * ?`（application.yml 已添加）
  - 策略：按截止时间分页批删（每批500）
- 控制器异常兜底（AOP）
  - 切面：backend/src/main/java/com/filemanager/audit/ApiAuditAspect.java
  - 作用：在控制器抛异常时记录失败日志（actionType=API_{METHOD}，resourceType=API，resourceName=URI），基于当前用户（仅认证用户，避免 user_id 为空）

验证建议
- 导出：
  - 使用与分页列表相同的筛选条件导出 CSV/XLSX，核对列头与内容；超出 `maxRows` 时截取至上限
- 清理：
  - 造出过期数据（手动回填 create_time），等待或手动触发 CRON 时间后，检查过期日志被批量清理
- 异常兜底：
  - 人为触发控制器异常（例如传递非法参数），验证日志中出现 `API_{METHOD}` 的失败记录
