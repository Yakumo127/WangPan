# 分享模块限速与分页落地（2025-11-27 13:17）

## 1. 问题成因
- 公开分享直链下载仍未加速率限制，容易被批量拉取或爬虫耗尽带宽。
- “我的分享”以及公开分享内容列表目前由前端或内存做分页，缺少后端分页的接口与数据结构，导致大数据量时性能和体验不可控。

## 2. 排查过程与历史
- 2025-11-27 12:35 已记录“限速与分页”待落地，但当时未动代码，仅在报告中标注“即将实施”。
- 查看后端 `DownloadTokenService` 已预留 `download.rate-limit-bytes-per-second`，但未在控制器套用，也未提供默认值与系统配置。
- `ShareController` `/api/shares` 直接返回全量列表；`/api/public/shares/{id}/list` 在内存排序/截断，没有 Page 结构。
- 前端 `Share.vue` 仍使用本地过滤，未接入分页；公开页 `SharePublic.vue` 仅做前端分页。

## 3. 修复建议
- 在直链下载接口添加限速输送（默认 3MB/s），并允许通过配置调整或关闭（配置项 <=0 视为不限速）。
- `我的分享`、`公开分享内容` 接口提供 page/size/sort，返回 `total + items`，按创建时间倒序。
- 前端分享列表/公开页接入后端分页参数与分页组件，减少一次取全量。
- 继续遵循“受控模式 + ACL(USER) 待办，公开模式默认可下载”约束，不引入邮件发送。

## 4. 实际采取的修复操作
- 将 `download.rate-limit-bytes-per-second` 默认值调整为 3MB/s，公开直链与用户直链下载均按该限速传输（<=0 关闭），加入文件直链限速实现。
- `/api/shares` 支持 `page/size`，返回 `total/items` 与汇总统计（总数/有效数/浏览/下载）；公开列表 `/api/public/shares/{id}/list` 改为数据库分页并返回 `total/items`。
- 前端 `Share.vue` 接入分页参数/UI，适配分页返回与统计字段；`SharePublic.vue` 使用后端分页数据驱动翻页。
- 保持审计打点逻辑，未新增额外通知流程。

## 5. 风险与回滚
- 若限速配置过低会拖慢正常下载，需在系统设置或配置文件中可调；如出现下载阻塞，可将 `download.rate-limit-bytes-per-second` 设为 0 关闭。
- 分页接口变更需前端同步；若出现兼容问题，可临时放宽 size（例如 500）作为缓冲。

## 6. 测试计划
- 后端打包 `mvn -pl backend -am package -DskipTests`。
- 调用 `/api/public/shares/direct-download` 验证速率限制是否生效（大文件下载观察吞吐）。
- `/api/shares?page=0&size=10` 返回 `total/items` 结构，分页准确。
- `/api/public/shares/{id}/list?page=0&size=10` 返回 Page 结构，翻页数据准确且只包含分享子树。
