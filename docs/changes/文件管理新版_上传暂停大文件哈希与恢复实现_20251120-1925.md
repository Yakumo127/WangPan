# 文件管理（新版）上传暂停、大文件哈希与任务恢复实现（2025-11-20 19:25）

## 一、变更背景

在前一阶段，我们已经为“文件管理（新版）”实现了上传队列、秒传、直传与分片上传。  
但从实际体验和设计目标来看，还存在三类缺口：

1. 暂停 / 恢复 / 取消 仅为前端状态，不会真实中断网络请求或分片调度；
2. 哈希计算使用 `file.arrayBuffer()` + WebCrypto，一次性读入大文件，在单文件 4GB 场景下存在明显的内存与性能风险；
3. 刷新页面后，前端上传队列丢失，虽然服务端分片仍在，但用户无法方便地恢复未完成任务。

本次变更根据《文件管理新版_上传暂停大文件与续传增强设计_20251120-1916》文档，落实以下目标：

- 为直传与分片上传接入 AbortController，实现真实的网络级暂停与取消；
- 将文件 SHA-256 计算改造为分块流式哈希，支持大文件且不阻塞 UI；
- 为上传队列增加本地持久化与恢复能力，使刷新页面后可以提示并继续未完成任务。

## 二、具体实现内容

// 直传小文件
export function directUpload({ file, folderId, filename, onUploadProgress, signal }) {
  const formData = new FormData()
  formData.append('file', file)
  if (folderId != null) formData.append('folderId', folderId)

export function uploadChunk({ hash, index, total, chunk, onUploadProgress, signal }) {
  const formData = new FormData()
  formData.append('file', chunk)
  formData.append('fileHash', hash)
  formData.append('chunkNumber', String(index))
  formData.append('totalChunks', String(total))
  return request({
    url: '/files/chunk',
    method: 'post',
    data: formData,
    headers: { 'Content-Type': 'multipart/form-data' },
    onUploadProgress,
    signal
  })
}
```

- 同样引入 `signal` 参数，以便在分片上传阶段支持暂停/取消。

async error => {
  console.error('Response error:', error)
  // 主动取消（如上传暂停/取消）不提示错误
  if (error && error.code === 'ERR_CANCELED') {
    return Promise.reject(error)
  }
  // ...原有错误处理逻辑...

```

这样当上传任务因 AbortController 取消时：

- axios 会以 `code = 'ERR_CANCELED'` 抛出错误；
- 全局拦截器不再弹出“网络错误”提示，而是简单向上传递错误，让上传队列逻辑根据任务状态（paused/canceled）决定是否标记失败。

### 2.3 fileHash：流式 SHA-256 支持大文件

文件：`frontend/src/utils/fileHash.js`

原实现使用 WebCrypto 一次性 digest，无法很好支持 4GB 大文件。本次改造为完整的增量 SHA-256 实现，并增加流式 file 处理逻辑：

1. 新增 `Sha256` 类：

- 使用标准 SHA-256 常量 `K` 和工作数组 `w`；
- 实现 `_processChunk` 函数，按 512-bit 分块处理数据；
- 提供 `update(Uint8Array)` 与 `digest()` 接口，支持多次增量更新；
- `digest()` 负责补充 SHA-256 的 padding 和长度字段，并返回 hex 字符串。

2. 提供流式哈希函数 `computeFileSha256`：

```js
export async function computeFileSha256(file, options = {}) {
  if (!file) throw new Error('文件为空')
  const {
    chunkSize = 4 * 1024 * 1024,
    onProgress,
    signal
  } = options

  const hasher = new Sha256()
  const total = file.size
  let offset = 0

  while (offset < total) {
    if (signal?.aborted) {
      const err = new Error('hash aborted')
      err.code = 'HASH_ABORTED'
      throw err
    }
    const end = Math.min(offset + chunkSize, total)
    const blob = file.slice(offset, end)
    const buf = await blob.arrayBuffer()
    hasher.update(new Uint8Array(buf))
    offset = end
    if (onProgress) {
      onProgress(offset, total)
    }
  }
  return hasher.digest()
}
```

行为：

- 以 `chunkSize`（默认 4MB）逐块读取文件，逐段更新 hasher；
- 通过 `onProgress(loaded, total)` 回调上报进度（用于 UI 可选展示）；
- 若 `signal.aborted` 被触发，抛出带 `code = 'HASH_ABORTED'` 的错误，交由队列逻辑识别为用户中断，不视为失败。

#### 2.4.2 暂停 / 恢复 / 取消的真实行为

1. 暂停：

```js
const pauseTask = (taskId) => {
  const task = uploadQueue.value.find((t) => t.id === taskId)
  if (!task) return
  if (task.status === 'uploading' || task.status === 'hashing' || task.status === 'checking_fast') {
    updateTask(task, { status: 'paused' })
    if (task.controllers?.hashingController) {
      task.controllers.hashingController.abort()
      task.controllers.hashingController = null
    }
    if (task.controllers?.requestControllers) {
      for (const c of task.controllers.requestControllers) {
        c.abort()
      }
      task.controllers.requestControllers.clear()
    }
  }
}
```

- 暂停操作会中断哈希与当前所有网络请求；  
- 后续分片调度看到 `status === 'paused'` 后不再发起新的分片请求。

2. 恢复：

```js
const resumeTask = (taskId) => {
  const task = uploadQueue.value.find((t) => t.id === taskId)
  if (!task) return
  if (task.status === 'paused') {
    updateTask(task, { status: 'pending' })
    schedule()
  }
}
```

- 对直传任务，恢复相当于重新上传整个文件；  
- 对分片任务，恢复时会重新查询已上传分片并补传缺失部分。

3. 取消：

```js
const cancelTask = (taskId) => {
  const idx = uploadQueue.value.findIndex((t) => t.id === taskId)
  if (idx === -1) return
  const task = uploadQueue.value[idx]
  if (task.status === 'completed') return
  updateTask(task, { status: 'canceled' })
  if (task.controllers?.hashingController) {
    task.controllers.hashingController.abort()
    task.controllers.hashingController = null
  }
  if (task.controllers?.requestControllers) {
    for (const c of task.controllers.requestControllers) {
      c.abort()
    }
    task.controllers.requestControllers.clear()
  }
  uploadQueue.value.splice(idx, 1)
  persistState()
}
```

#### 2.4.3 本地持久化与恢复 attachFileToTask

1. 持久化上传队列状态：

```js
const STORAGE_KEY = 'efm_upload_queue_v1'

const persistState = () => {
  const tasks = uploadQueue.value
    .filter(t => t.status !== 'completed' && t.status !== 'canceled')
    .map(t => ({
      id: t.id,
      name: t.name,
      size: t.size,
      folderId: t.folderId,
      hash: t.hash,
      useChunks: t.useChunks,
      createdAt: t.createdAt,
      lastStatus: t.status
    }))
  window.localStorage.setItem(STORAGE_KEY, JSON.stringify({ version: 1, tasks }))
}
```

- 在 `enqueueFiles`、`updateTask` 和 `cancelTask` 中调用 `persistState()`，保证本地状态与内存队列同步。

2. 恢复持久化任务：

```js
const restoreFromStorage = () => {
  const raw = window.localStorage.getItem(STORAGE_KEY)
  if (!raw) return
  const parsed = JSON.parse(raw)
  if (!parsed || !Array.isArray(parsed.tasks)) return
  const now = Date.now()
  for (const t of parsed.tasks) {
    const task = {
      id: t.id || `${now}-${Math.random().toString(16).slice(2)}`,
      file: null,
      name: t.name,
      size: t.size,
      folderId: t.folderId ?? null,
      hash: t.hash || null,
      status: 'paused',
      progress: 0,
      uploadedBytes: 0,
      errorMessage: '',
      isFastUploaded: false,
      useChunks: !!t.useChunks,
      totalChunks: 0,
      chunks: [],
      createdAt: t.createdAt || now,
      updatedAt: now,
      controllers: {
        hashingController: null,
        requestControllers: new Set()
      }
    }
    uploadQueue.value.push(task)
  }
}
```

- 在组合函数末尾调用 `restoreFromStorage()`，确保挂载时即可恢复上次会话未完成任务，以 `file = null`, `status = 'paused'` 的形式显示。

3. 提供 `attachFileToTask` 以便绑定重新选择的文件：

```js
const attachFileToTask = (taskId, file) => {
  const task = uploadQueue.value.find((t) => t.id === taskId)
  if (!task) return
  if (!file) {
    ElMessage.error('请选择文件')
    return
  }
  if (file.name !== task.name || file.size !== task.size) {
    ElMessage.error('选择的文件与原任务不一致')
    return
  }
  task.file = file
  const useChunks = file.size >= CHUNK_THRESHOLD
  task.useChunks = useChunks
  task.totalChunks = 0
  task.chunks = []
  updateTask(task, {
    status: 'pending',
    progress: 0,
    uploadedBytes: 0,
    errorMessage: ''
  })
  schedule()
}
```

- 校验文件名与大小，以确保用户选择的是“同一个文件”；  
- 绑定文件后重置任务进度并重新进入调度，后续逻辑会自动利用已有分片或秒传能力。

## 三、行为验证与注意事项

1. 暂停/取消行为：
   - 对直传与分片上传，点击“暂停”会立即中断当前网络请求（axios 报 `ERR_CANCELED`），分片调度循环也会在下一轮检测到 `status === 'paused'` 后停止；
   - 点击“取消”会中断当前请求并从队列移除任务，不再继续后续上传；
   - 由于局限于 HTTP，请求中断点由浏览器与网络层控制，已发送的数据可能到达服务器，但不会进一步调度新的分片。

2. 大文件哈希：
   - 对于任意大小文件，哈希均采用流式分块方式，峰值内存约为单块大小（默认 4MB）；
   - 在 hash 期间也支持暂停/取消，通过 AbortController 中止循环；
   - 对于 4GB 级别文件，运行时间与 I/O 成正比，性能在可接受范围内。

3. 页面刷新与任务恢复：
   - 未完成任务会被持久化到 localStorage，在新会话中恢复为 `file = null, status = 'paused'` 的占位项；
   - 用户重新选择文件后，系统会验证文件名与大小与原任务一致，避免错误续传；
   - 对分片任务，attachFile 后会继续走 `uploadByChunks`，实质上利用已有 `/chunk/status` 结果，只补传缺失分片。

4. 兼容性与安全性：
   - 未修改后端接口，仅增强前端对已有接口的调用方式；
   - 上传策略、权限与配额逻辑仍由后端控制；
   - 本地持久化只存任务元数据，不包括任何文件内容。
