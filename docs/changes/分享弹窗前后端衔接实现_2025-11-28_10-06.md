# 分享弹窗前后端衔接实现（2025-11-28 10:06）

## 问题成因
- 后端 `ShareService` 在创建/更新分享时未将请求体中的 `shareMode` 写入实体，导致所有分享被默认为 `PUBLIC`，切换模式无效，也会影响公开模式高风险权限兜底的语义。
- 前端新样式的分享弹窗虽然对接了接口，但生成的分享链接缺少 `/#/`（项目使用 Hash 路由），直接复制访问会 404；同时上传权限未根据资源类型/模式做前置过滤，容易与后端兜底产生不一致。

## 排查过程与历史
- 查阅 `backend/src/main/java/com/filemanager/service/ShareService.java`，确认 `createShare`/`updateShare` 仅调用 `sanitizePermissions`，但未调用 `share.setShareMode(...)`；`Share` 实体默认 `shareMode=PUBLIC`，因此创建/编辑都不会持久化切换结果。
- 查看 `frontend/src/views/Share.vue`，`shareUrl` 由 `window.location.origin + '/s/' + id` 拼装，忽略了 Hash 路由前缀；`allowUpload` 直接由复选框决定，未对“文件类型”或“公开模式”做二次约束。
- 参考 `docs/specs/分享模块功能拆解与操作日志要求_20251127-1024.md` 与 11 月 27 日系列实现文档，确认公开模式禁用高风险位、Hash 路由访问 `/s/:id` 是既定约束。

## 修复建议
- 后端：在创建/更新分享时显式写入请求的 `shareMode`，结合既有 `sanitizePermissions` 保证公开模式兜底禁用上传/再分享/删移。
- 前端：分享链接拼接补全 `/#/s/:id`；`allowUpload` 仅在“文件夹 + 受控模式 + 用户勾选上传”时传 true，其余情况传 false，并在类型/模式切换时剔除上传勾选，避免与后端兜底冲突。

## 实际采取的修复操作
- 后端：在 `ShareService.createShare` 与 `ShareService.updateShare` 中增加 `share.setShareMode(req.getShareMode())`，确保创建/编辑后的分享模式正确持久化并驱动权限兜底。
- 前端：`Share.vue` 中将 `shareUrl` 改为 `window.location.origin + '/#/s/' + id`；创建/编辑 payload 的 `allowUpload` 增加资源类型与模式校验，并在类型切换 watch 中移除上传选项，保证请求与后端校验一致。

## 验证
- 静态检查：创建/编辑分享切换模式后请求体包含正确的 `shareMode`，`allowUpload` 仅在“文件夹 + 受控”时为 true；复制的分享链接形如 `http(s)://host/#/s/{id}`，符合 Hash 路由。
- 未执行端到端跑通，如需进一步确认可本地起前后端后按“创建分享→编辑模式→打开分享链接”流程验证。
