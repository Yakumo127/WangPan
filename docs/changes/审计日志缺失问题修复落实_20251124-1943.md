# 审计日志缺失问题修复落实（2025-11-24 19:43）

## 问题成因
- 审计服务与切面将异常静默吞掉，SpEL 解析或持久化失败无告警，日志直接丢失。
- 匿名/系统级操作无兜底主体，`system/admin` 缺失时审计记录被跳过。
- 关键路径（注册、资料更新、改密）缺少 `@AuditedOperation`，且控制器内部捕获异常返回 4xx，导致失败未入库。

## 排查过程
1. 通读 `AuditLogService`，发现 `save` 捕获异常后直接 `ignore`，`userId` 解析失败即返回。
2. 查看 `ServiceAuditAspect` 与 `ApiAuditAspect`，均将异常吞掉且不落告警。
3. 梳理 `UserService`，注册/改密/资料更新未打审计注解；`AuthController` 内部 try-catch 返回 400，不会触发 API 异常切面。

## 修复建议与本次落实项
- 增强可观测性：切面与审计服务遇到 SpEL/持久化异常时记录告警日志，并在 SpEL 失败时写系统级审计失败兜底。
- 兜底主体：解析不到用户时回退/创建 `system` 用户，必要时回退 `admin`。
- 覆盖缺口：为注册、资料更新、修改密码补齐 `@AuditedOperation`，确保成功/失败均有审计。
- 保留错误信息：审计失败时截断错误文本同时写告警日志，便于排查。

## 本次实际修复
- `AuditLogService`：新增日志告警，审计用户缺失时自动回退/创建 `system` 账号（再回退 `admin`），审计写入异常输出 warn 便于排查。
- `ServiceAuditAspect`：记录 SpEL/持久化异常的 warn，并尝试写系统级失败审计兜底。
- `ApiAuditAspect`：控制器异常/成功兜底场景增加 warn，匿名/用户/系统级写入失败都会记录错误。
- `UserService`：为注册、更新个人资料、修改密码补齐审计注解；补充 `UserLog.ACTION_REGISTER` 常量。
