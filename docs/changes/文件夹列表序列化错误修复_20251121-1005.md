# 文件夹列表序列化错误修复（2025-11-21 10:05）

## 问题成因
- 前端在新建文件夹时调用 `/api/folders/list` 返回 500，后端日志报 `Type definition error: [simple type, class org.hibernate.proxy.pojo.bytebuddy.ByteBuddyInterceptor]`。
- `FolderController.getUserFolders` 直接返回 `Folder` 实体列表，`Folder` 与 `parent/children/files` 存在双向关联且开启懒加载，序列化时拿到 Hibernate 代理对象（ByteBuddyInterceptor），Jackson 未能正确处理，导致 500。

## 排查过程
- 重现：调用 `/api/folders/list?parentId=1` 报 500，创建文件夹后同样报错且无法打开目录。
- 定位：错误发生在 `Folder` 实体序列化阶段；该实体仅对 `user` 做了 `@JsonIgnore`，`parent`、`children`、`files` 未忽略，返回实体时触发懒加载代理序列化。

## 解决思路
- 避免直接序列化代理：对 `Folder` 实体增加 `@JsonIgnoreProperties`/`@JsonIgnore`，忽略 `parent`、`children`、`files`、`hibernateLazyInitializer`、`handler`，只暴露必要字段（id/name/time）。
- 保持业务逻辑不变，接口返回仍为实体列表，但裁剪掉易引发代理序列化的字段。

## 实际修复操作
- `backend/src/main/java/com/filemanager/entity/Folder.java`：
  - 类上添加 `@JsonIgnoreProperties({"hibernateLazyInitializer","handler","parent","children","files"})`。
  - 在 `parent` 字段上补充 `@JsonIgnore`，避免递归序列化。

## 影响评估
- 返回 JSON 将不再包含 parent/children/files 字段（前端列表不依赖这些字段），序列化恢复正常。
- 仅调整序列化视图，不影响数据库或业务逻辑，风险低。***
