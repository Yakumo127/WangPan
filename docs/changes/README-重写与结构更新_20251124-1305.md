# README 重写与结构更新（2025-11-24 13:05）

## 问题成因
- 根目录 `README.md` 最初写于项目早期版本，仅覆盖基础功能与部署方式，多处描述已与当前 2.x 版本实现不完全一致。
- 目录结构示例仍使用旧的顶层目录名（如 `test11/`），与当前仓库目录结构、启动脚本描述存在偏差，容易误导后续维护者。
- 当前 README 对于近期落地的能力（如大文件分片上传与秒传、下载直链与一次性 Token、文件预览增强、移动/复制交互优化等）没有做统一汇总与串联，信息分散在 `docs` 多份文档中，缺乏“单一入口”的总览文档。
- 部署与本地开发章节中，部分环境版本（Node.js 版本、H2 开发环境脚本等）与实际使用脚本（`setup-env.sh`、`h2-start.sh`、`start-project.sh` 等）之间存在出入，导致新同学很难直接按 README 成功跑起来。

## 排查过程与历史
- 通读现有根目录 `README.md`，梳理其章节结构，包括：项目概述、核心特性、目录结构、项目架构、数据库架构、API 接口文档、部署指南、已实现功能、系统监控、开发指南、版本历史、许可证、技术支持等。
- 对照后端 `backend/pom.xml`，确认当前后端技术栈：Spring Boot 3.2.0、Java 17、MySQL 8.0.33、Redis、JWT、JPA/Hibernate 以及 Hutool、Lombok、Apache POI 等，版本信息与 README 中原有说明基本一致，但 README 中版本号仍标注为 `v1.0.0`。
- 检查前端 `frontend/package.json`，确认实际使用 Vue 3.3.0、Element Plus 2.4.0、Pinia 2.1.0、Vue Router 4.2.0、Axios 1.6.0 等，与 README 原有技术栈描述一致，但 README 未体现 2.0.0 版本以及 PDF 预览（`pdfjs-dist`）等新增依赖。
- 查看 `start-project.sh`、`simple-start.sh` 与 `h2-start.sh`，发现：
  - 脚本使用 `npm run dev` 启动前端，而 `package.json` 中定义的脚本为 `npm run serve`，说明脚本与前端脚手架存在一定历史遗留不一致；
  - `h2-start.sh` 会直接覆盖 `backend/src/main/resources/application.yml`，切换到 H2 内存数据库用于开发调试，这一行为在 README 中没有被强调，容易导致配置被意外覆盖。
- 查阅 `docs/changes`、`docs/specs`、`docs/troubleshooting` 下的多份文档，确认以下近期重要能力已经实现但未在 README 中集中体现：
  - 文件预览功能及其多轮修复、PDF 预览方案与 pdfjs 接入；
  - 下载直链与一次性 Token 设计与实施；
  - 文件管理（新版）上传队列、大文件分片与秒传、移动/复制目录请求去重、图片预览弹窗优化等。
- 结合以上信息，确定需要在不改变原有大纲结构的前提下，系统性重写 README，使其成为当前版本的“权威说明文档”。
