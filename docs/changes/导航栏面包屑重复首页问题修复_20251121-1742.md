# 导航栏面包屑重复“首页”问题修复（2025-11-21 17:42）

## 问题成因
- 布局文件 `frontend/src/layout/index.vue` 中在面包屑模板里写死了一个指向 `/` 的“首页”。
- 同一模板随后遍历 `route.matched` 中所有带 `meta.title` 的路由生成面包屑；根路由 `/` 与其默认子路由 `''` 均配置了 `meta.title='首页'`，导致在首页渲染为“首页 / 首页 / 首页”。
- 访问其他页面（如 `/files-explorer`）时，父级仍然是“首页”，子级是该页面标题，于是渲染为“首页 / 首页 / 文件管理（新版）”；只有头部写死的第一个“首页”带跳转，后两个不可点击。

## 排查过程与历史
- 复现：在浏览器访问 `http://192.168.10.2:3000/#/` 看到导航栏“首页 / 首页 / 首页”；跳转到“文件管理（新版）”看到“首页 / 首页 / 文件管理（新版）”。
- 代码定位：查阅 `frontend/src/layout/index.vue` 发现面包屑存在硬编码根节点及基于 `route.matched` 的重复渲染。查阅 `frontend/src/router/index.js` 确认根路由与默认子路由均配置了 `meta.title='首页'`，且所有子路由均有标题，意味着任何页面都会至少产生两级“首页”。
- 现状判定：问题由模板与路由元信息叠加产生；无需改动路由结构，只需调整面包屑渲染逻辑即可消除重复。

## 修复建议
- 移除面包屑中写死的“首页”，改为仅渲染当前活跃路由的最后一层标题。
- 面包屑计算逻辑只取 `route.matched` 最后一个带 `meta.title` 的路由作为当前页标题；当路由切换时动态更新。
- 保持现有路由结构与 `meta.title` 配置不变，以减少改动范围。

## 实际采取的修复操作
- 调整 `frontend/src/layout/index.vue` 模板，删除固定的“首页”面包屑项，面包屑仅渲染一个当前页标题。
- 新增 `currentBreadcrumbTitle` 计算属性，过滤 `route.matched` 并取最后一个有 `meta.title` 的路由标题作为展示文案。
- 面包屑项不再重复父级标题，首页仅显示一个“首页”，访问“文件管理（新版）”仅显示一个“文件管理（新版）”，其他页面同理。

## 验证与预期
- 打开首页 `/`：导航栏显示“首页”且无多余分隔符。
- 打开“文件管理（新版）” `/files-explorer`：导航栏显示“文件管理（新版）”。
- 打开“仪表盘” `/dashboard`：导航栏显示“仪表盘”。
- 面包屑不再出现冗余项，不存在不可点击的重复“首页”。
