# 文件预览：新版预览页细节优化（2025-11-20 18:01）

## 一、需求回顾

在新增 `/file-view/:id` 路由与 `PreviewNew.vue` 预览页后，用户提出以下细节优化需求：

1. 顶部标题文本需要从“企业文件管理系统 - 文件名...”改为“文件名：xxx”，突出文件名本身；
2. 顶部操作区域中，在“返回文件列表”和“下载”按钮之间增加“详情”按钮：
   - 默认情况下右侧文件信息栏不展示；
   - 仅当点击“详情”按钮时才显示右侧文件信息栏；
3. 文件信息区域排版不够美观且信息不够丰富：
   - 需要优化布局，避免局促；
   - 增加以下字段：文件大小、上传时间、修改时间、位置；
4. 顶部操作区域增加“历史”按钮，当前阶段仅占位，不实现具体功能。

要求：在不影响现有 `/preview/:id` 预览逻辑的前提下，对新预览页 `/file-view/:id` 做上述 UI 与数据展示优化。

## 二、整体设计

1. 顶部标题调整
- 由原来的“系统名 + 文件名”改为更聚焦文件的表达：
  - 旧：`企业文件管理系统 - 文件名`；
  - 新：`文件名：{{ filename }}`；
- 保留顶部栏整体结构与配色不变，仅修改文案与样式。

2. 顶部操作按钮组

由原来的：

```vue
<el-button size="small" @click="goBack">返回文件列表</el-button>
<el-button size="small" @click="handleDownload">下载</el-button>
```

调整为：

```vue
<el-button size="small" @click="goBack">返回文件列表</el-button>
<el-button size="small" @click="toggleDetails">详情</el-button>
<el-button size="small" @click="handleHistory">历史</el-button>
<el-button size="small" @click="handleDownload">下载</el-button>
```

- “详情”按钮：控制右侧信息栏的显示/隐藏，通过布尔状态 `showSidebar` 实现：
  - 默认 `showSidebar = false`；
  - 点击“详情”切换 `showSidebar`；
  - 仅当 `showSidebar` 为 `true` 时渲染左侧文件信息栏。
- “历史”按钮：当前仅作为占位按钮，不触发任何后端调用：
  - 可简单在控制台打印日志或使用 `ElMessage.info('历史功能暂未实现')` 提示。

3. 文件信息栏展示内容

右侧信息栏内容（`PreviewNew.vue` 中的 `<aside>` 部分）调整为包含以下字段：

- 名称：文件名；
- 类型：基于 `viewerType` 的中文描述（PDF 文件 / 文本文件 / 视频文件 / Office 文档 / 其他类型）；
- 大小：格式化后的大小（例如 `1.23 MB`）；
- 上传时间：文件创建时间（由列表页传入的 `createTime`）；
- 修改时间：文件修改时间（由列表页传入的 `updateTime`，如无则可为空或显示“未知”）；
- 位置：文件所在目录或路径（由列表页传入的 `location`，如无则显示“根目录”或“未知”）。

数据来源：

- 为保持后端无改动，本次从文件列表页 `List.vue` 的行数据中，将已有字段通过路由 query 传给 `PreviewNew.vue`，包括：
  - `size`：`row.size`；
  - `createTime`：`row.createTime`；
  - `updateTime`：若有则传入，否则为空；
  - `location`：若接口已有目录信息字段（例如 `folderPath` / `path`），则传入；如暂未提供，则本次先留空或显示默认文案。

在 `PreviewNew.vue` 中：

- 使用格式化函数将 `size` 与时间字段转为可读字符串：
  - 大小：复用列表页的 `formatFileSize` 逻辑；
  - 时间：使用 `new Date(...).toLocaleString()`；
- 防御性处理：如对应 query 字段不存在或为空，则显示空字符串或友好提示（如“未知”“根目录”）。

4. 文件信息栏布局优化

- 保持固定宽度（约 260px），但调整内部排版：
  - 增大行间距与段落间距；
  - 标题使用更明显的字号和粗体；
  - 字段以“标签 + 值”的上下结构展示，避免挤在同一行；
  - 通过颜色区分标签（浅色）和内容（较深颜色）。
- 示例样式：

```css
.file-preview-sidebar {
  width: 260px;
  border-right: 1px solid #ebeef5;
  padding: 16px;
  box-sizing: border-box;
  background: #fafafa;
}

.sidebar-title {
  margin: 0 0 16px;
  font-size: 14px;
  font-weight: 600;
  color: #333;
}

.sidebar-section {
  margin-bottom: 14px;
}

.sidebar-label {
  font-size: 12px;
  color: #909399;
  margin-bottom: 4px;
}

.sidebar-value {
  font-size: 13px;
  color: #333;
  word-break: break-all;
}
```

整体目标是：信息栏更“松一点”，信息更全，阅读体验更好。

## 三、前端实现要点

1. `PreviewNew.vue` 调整

- 标题部分：
  - 将 `.system-name` + 分隔符 + `.file-name` 调整为单一行“文件名：xxx”；
- 新增状态：
  - `const showSidebar = ref(false)`；
- 新增方法：
  - `toggleDetails`：切换 `showSidebar`；
  - `handleHistory`：暂时仅提示“历史功能暂未实现”；
- `<aside>` 使用 `v-if="showSidebar"` 控制是否渲染信息栏；
- 增加获取 query 中 `size/createTime/updateTime/location` 的逻辑，并格式化展示。

2. `List.vue` 调整

- 在 `openNewPreview(file)` 中，将额外字段通过 query 传递给新预览页：

```js
const openNewPreview = (file) => {
  router.push({
    name: 'FilePreviewNew',
    params: { id: file.id },
    query: {
      name: file.originalFilename || file.name || '',
      size: file.size || '',
      createTime: file.createTime || '',
      updateTime: file.updateTime || '',
      location: file.folderPath || ''
    }
  })
}
```

- 考虑到当前 file 列数据中可能暂不含 `updateTime` 或 `folderPath`，在 `PreviewNew.vue` 中对这些字段进行空值处理。

## 四、影响评估

1. 对现有功能的影响
- `/file-view/:id` 新预览页目前仅通过列表中的“预览”按钮进入，原有点击文件名 → `/preview/:id` 路径不变；
- 后端接口不做任何改动；  
- 图片预览仍走列表页对话框逻辑，不受影响。

2. 风险
- 本次改动集中在 `PreviewNew.vue` 和 `List.vue` 的 query 透传与布局调整；
- 若列表数据中暂时缺少部分字段（例如修改时间、位置），新预览页通过空值处理避免抛错，仅表现为对应信息留空或默认文案；
- “历史”按钮目前仅占位，不触发实际业务逻辑，风险极低。

## 五、小结

本次优化针对新预览页 `/file-view/:id` 做了以下改进：

- 顶部标题更聚焦文件名；
- 顶部按钮组新增“详情”和“历史”，其中“详情”控制信息栏显示，“历史”占位；
- 文件信息栏布局更舒展，信息更完整（名称、类型、大小、上传时间、修改时间、位置）；
- 保持新预览页仍为“试验版本”，与旧预览页逻辑解耦，便于后续继续迭代体验。
