# 文件预览体验修复：图片对话框与 PDF iframe（2025-11-20 14:37）

本文记录“文件预览”功能落地后的两个体验问题及修复方案：图片（png）预览无任何界面反馈、PDF 预览在 Network 为 200 的情况下依然报 Axios 超时错误。该文档作为补充说明，对应的整体预览设计见《docs/specs/文件预览功能设计方案_20251120-1324.md》，实现过程见《docs/changes/文件预览功能_实施记录_20251120-1338.md》。

## 一、问题 1：图片（png）预览无界面反馈

### 1.1 现象

- 在文件列表页（`/files`）中，点击一个扩展名为 `png` 的文件名：
  - 浏览器 Network 显示：`GET /api/files/{id}/preview` 状态码为 200，响应体中也包含图片数据；
  - 但页面上没有任何弹窗或预览区域出现，看起来“没有反应”。

### 1.2 成因分析

前端图片预览逻辑位于 `frontend/src/views/files/List.vue`：

- 单击文件名时，通过 `onFileNameClick(row)` 判断是否为图片类型（`jpg/jpeg/png`），若是则调用：
  ```js
  const previewImage = async (file) => {
    const resp = await previewFileApi(file.id)  // GET /api/files/{id}/preview
    const blob = resp?.data
    const url = window.URL.createObjectURL(blob)
    imagePreviewUrl.value = url
    imagePreviewVisible.value = true
  }
  ```
- 组件内已定义用于控制图片预览状态的变量：
  - `const imagePreviewVisible = ref(false)`
  - `const imagePreviewUrl = ref('')`

问题在于：**模板中没有任何 `el-dialog` 或 `<img>` 使用这两个状态**。  
也就是说：

- 预览请求确实发出了，后端也正常返回图片数据；
- 前端也生成了 `imagePreviewUrl` 并将 `imagePreviewVisible` 设为 true；
- 但由于没有对应的 DOM 结构显示该图片，对用户而言就成了“点击文件名无任何反应”。

### 1.3 修复方案与改动

在 `frontend/src/views/files/List.vue` 模板根结尾处新增图片预览对话框：

- 新增模板片段：
  ```vue
  <el-dialog v-model="imagePreviewVisible" title="图片预览" width="60%">
    <img
      v-if="imagePreviewUrl"
      :src="imagePreviewUrl"
      style="max-width:100%;max-height:70vh;display:block;margin:0 auto;"
    />
  </el-dialog>
  ```

这样：

- 点击 `png/jpg/jpeg` 文件名后：
  - `previewImage` 会从 `/api/files/{id}/preview` 拉取 blob，生成 object URL；
  - 设置 `imagePreviewUrl` 与 `imagePreviewVisible = true`；
  - 对话框弹出并显示图片，用户可以关闭对话框返回列表。

## 二、问题 2：PDF 预览 200 OK 但 Axios 超时

### 2.1 现象

- 用户在列表页点击一个 pdf 文件名 → 路由跳转到预览页（`/preview/:id`）；  
- Network 中对 `GET /api/files/{id}/preview` 的请求：
  - 状态码：200 OK；
  - 数据（pdf 内容）已经传输完成；
- 但控制台报错：
  - `AxiosError: timeout of 300000ms exceeded`，`code: 'ECONNABORTED'`；
  - 被全局拦截器翻译为“网络错误，请检查您的网络连接”，导致预览页显示“加载预览失败”。

### 2.2 成因分析

预览页实现位于 `frontend/src/views/files/Preview.vue`，原始实现为：

- 使用 axios 拉取预览内容：
  ```js
  import { previewFile as previewFileApi } from '@/api/file'

  const loadPreview = async () => {
    const res = await previewFileApi(fileId)   // GET /files/{id}/preview, responseType:'blob', timeout:300000
    const blob = res?.data
    const url = window.URL.createObjectURL(blob)
    blobUrl.value = url
  }
  ```
- 模板中再用 `blobUrl` 作为 `<iframe>` 或 `<video>` 的数据源。

问题在于：

- 该接口是流式响应（`StreamingResponseBody`），Axios 使用 XHR + 超时来管理请求；
- 在某些情况下，即便服务器已经开始或完成响应，Axios/浏览器侧对于“请求完全结束”的事件触发不稳定（特别是长连接、无 Content-Length 的流式输出）；
- 当 axios 的 `timeout: 300000` 计时器到点时，如果 XHR 没有进入“结束”状态，就会判定为超时并抛出 `ECONNABORTED`；
- 而此时 Network 里看到的 200 OK + body，只能说明“确实有响应到达”，但 axios 认为“这个请求没有正确结束”，因此被强行中断。

与之对比：

- 当用户在浏览器地址栏中直接打开 `/api/files/{id}/preview` 时：
  - 请求不经过 axios，不受我们设置的 timeout 约束；
  - 响应一旦到达就被浏览器内置的 PDF viewer 接管，能够正常预览；
  - 因此地址栏访问是正常的，而 Vue/axios 模式则被超时打断。

### 2.3 修复方案与改动思路

**原则**：对 pdf（以及后续可能的 office 文档）预览，不再使用 axios 拉 blob，而是让浏览器直接访问预览 URL：

- 新的预览方式：
  ```vue
  <iframe :src="`/api/files/${fileId}/preview`" class="preview-iframe" />
  ```
- 这样：
  - 预览页只是一个壳，内部 iframe 就像你在新标签打开 `/preview` 一样工作；
  - 浏览器直接把响应交给内置的 PDF viewer 或插件，完全绕过 axios 和 XHR 的 timeout 限制；
  - 不会再出现“Network 200 OK 但 axios timeout”的情况。

具体改动（`frontend/src/views/files/Preview.vue`）：

1. 去除对 `previewFileApi` 的依赖和 axios blob 拉取逻辑；
2. 保留顶部返回按钮和文件名展示；
3. 脚本中：
   - 通过 `route.params.id` 和 `route.query.name` 获取 fileId 与 filename；
   - 计算 `previewUrl = '/api/files/' + fileId + '/preview'`；
4. 模板中：
   - 对非视频类型统一使用：
     ```vue
     <iframe v-if="previewUrl" :src="previewUrl" class="preview-iframe" />
     ```
   - 对 mp4 等视频类型可改用 `<video :src="previewUrl" controls>`，同样直接使用 URL。

### 2.4 当前修复范围说明

- 本次仅将 PDF 预览方式由“axios+blob”调整为“iframe 直连 URL”，解决 timeout 与“看得到 200 却预览失败”的问题；
- 对 office 文档（doc/ppt 等）同样使用 iframe 直连，但预览效果仍取决于浏览器/插件支持情况；
- 真正的 doc/ppt → PDF 转换预览方案仍在 `docs/暂时搁置修复事项.md` 中登记为后续增强项。

## 三、验证要点

1. **图片预览**：
   - 点击 png/jpg/jpeg 文件名，确认出现图片预览对话框；
   - 关闭对话框后返回列表，未产生多余报错。

2. **PDF 预览**：
   - 点击 pdf 文件名，确认跳转到预览页，iframe 内由浏览器原生 PDF viewer 展示内容；
   - 控制台不再出现 `/files/{id}/preview` 的 axios timeout 错误；
   - 地址栏直接打开 `/api/files/{id}/preview` 与预览页 iframe 效果一致。

3. **其他类型**：
   - mp4 等视频类型可按后续规划进一步增强（如 `<video :src="previewUrl">`），当前以不破坏行为为前提。
