# 文件预览：位置真实路径实现（2025-11-20 18:11）

## 一、需求回顾

- 新预览页 `/file-view/:id` 已展示“位置”字段，但当前仅为占位实现：
  - 前端从路由 query 中读取 `location`，如为空则显示“根目录”；
  - 实际上传入的 `location` 来源是列表行上的 `file.folderPath || ''`；
  - 由于 `/files/list` 返回的 `File` JSON 中尚无 `folderPath` 字段，`location` 基本为空，因此“位置”并非真实路径。
- 用户希望按照“方案 B”完善“位置”显示：
  - 在不改变现有接口 URL 的前提下，使预览页和列表中展示的“位置”能够反映文件在目录结构中的真实路径。

## 二、设计思路

1. 数据来源
- 后端 `File` 实体中已经存在：
  - `folder`：指向所属 `Folder` 实体；
  - `Folder` 中包含 `name`、`parent`、`isRoot` 等字段，可构成完整的目录层级；
  - 但 `folder` 字段被 `@JsonIgnore` 标记，前端无法直接看到目录信息。
- 现有 `/files/list` 接口返回的是 `List<File>`，前端列表直接用这个 JSON 渲染：
  - 为避免大范围更改接口（例如改为 DTO），本次选择在 `File` 实体上增加一个 **只读的、非持久化的 JSON 属性** 来表示路径。

2. 核心方案

- 在 `com.filemanager.entity.File` 实体中新增一个计算属性：
  - `String getFolderPath()`：
    - 使用 `@Transient` 保证不会映射为数据库字段；
    - 使用 `@JsonProperty("folderPath")` 将其序列化到 JSON 输出；
    - 在 getter 中，通过 `folder` 的 `parent` 链构建逻辑路径字符串。
- 路径构建规则：
  - 从当前文件的 `folder` 开始向上遍历父目录链：
    - 遇到 `isRoot = true` 的目录，停止遍历，不将其名称加入路径；
    - 其余目录按从内到外的顺序收集名称；
  - 最终路径形态为：
    - 无上级目录时：`"/"`（根目录）；
    - 有目录链时：`"/部门A/项目X/子目录"` 这种以 `/` 为分隔符的层级路径。
- 前端使用：
  - 列表页 `List.vue` 已经使用 `file.folderPath || ''` 作为 `location` 源；
  - 新增属性后，无需再改这一部分，`location` 将自动变为真实路径；
  - 新预览页 `PreviewNew.vue` 中的 `locationLabel` 将展示实际路径字符串。

## 三、后端实现细节

1. 修改 `File` 实体

文件：`backend/src/main/java/com/filemanager/entity/File.java`

- 新增 import：

```java
import com.fasterxml.jackson.annotation.JsonIgnore;
import com.fasterxml.jackson.annotation.JsonProperty;
```

- 在类中添加 `getFolderPath` 方法：

```java
@Transient
@JsonProperty("folderPath")
public String getFolderPath() {
    Folder f = getFolder();
    if (f == null) {
        return "/";
    }
    java.util.List<String> names = new java.util.ArrayList<>();
    Folder cur = f;
    while (cur != null) {
        // 跳过标记为删除的目录
        if (Boolean.TRUE.equals(cur.getDeleted())) {
            break;
        }
        // 根目录（isRoot = true）不计入名称，但终止向上遍历
        if (Boolean.TRUE.equals(cur.getIsRoot())) {
            break;
        }
        String n = cur.getName();
        if (n != null && !n.isBlank()) {
            names.add(n);
        }
        cur = cur.getParent();
    }
    java.util.Collections.reverse(names);
    if (names.isEmpty()) {
        return "/";
    }
    return "/" + String.join("/", names);
}
```

注意点：

- 使用 `@Transient` 避免 Hibernate 将该属性视为列；
- 使用 `@JsonProperty("folderPath")` 保证在序列化为 JSON 时出现 `folderPath` 字段；
- 对删除标记和根目录做了简单防御：
  - 删除目录不再继续向上构建路径；
  - `isRoot = true` 的目录作为路径根，不将其名称展示出来。

2. 运行时行为

- `/files/list` 接口返回的 JSON 中，每个文件对象将新增一个字段：

```json
{
  "id": 123,
  "originalFilename": "报告.pdf",
  "size": 102400,
  "contentType": "application/pdf",
  "filePath": "...",
  "createTime": "...",
  "updateTime": "...",
  "folderPath": "/部门A/项目X"
}
```

- 对于位于根目录的文件，`folderPath` 将是 `"/"`。

## 四、前端配合（现状与收益）

1. 列表页 `List.vue`

- 在 `openNewPreview(file)` 中，`location` 使用的是 `file.folderPath || ''`：

```js
const openNewPreview = (file) => {
  router.push({
    name: 'FilePreviewNew',
    params: { id: file.id },
    query: {
      name: file.originalFilename || file.name || '',
      size: file.size || '',
      createTime: file.createTime || '',
      updateTime: file.updateTime || '',
      location: file.folderPath || ''
    }
  })
}
```

- 引入 `folderPath` 后，这里会自然拿到真实路径字符串：
  - 如果 `folderPath` 为 `/部门A/项目X`，则 `location` 也为该值；
  - 若 `folderPath` 为 `/`，则 `location` 为 `/`。

2. 新预览页 `PreviewNew.vue`

- 位置展示逻辑：

```js
const rawLocation = computed(() => route.query.location)

const locationLabel = computed(() => {
  const loc = (rawLocation.value || '').toString()
  if (!loc) return '根目录'
  return loc
})
```

- 效果：
  - 对于根目录文件：
    - `rawLocation = "/"`，`locationLabel` 显示为 `/`（如需显示“根目录”，可以后续再细调）；  
  - 对于有目录层级的文件：
    - `locationLabel` 显示完整路径 `/部门A/项目X`。

3. 其他页面

- 由于 `/files/list` 返回的 `File` JSON 在多个页面复用，`folderPath` 字段在其他地方也可按需使用（例如未来在列表中直接显示所属目录）；
- 未对该字段增加任何强绑定逻辑，现阶段只在新版预览页使用。

## 五、影响评估

1. 功能影响

- 位置字段从占位文案变为真实路径信息，预览页的“位置”展示更加准确；
- 不影响 `/preview/:id` 旧预览逻辑，只作用于新版预览页与未来可能使用 `folderPath` 的前端功能；
- 不改变任何接口路径和 HTTP 行为。

2. 性能与风险

- `getFolderPath` 在序列化时会访问 `folder` 及其 `parent` 链：
  - 文件列表较大时可能触发额外的懒加载查询（N+1），在当前规模下风险可接受；
  - 若后续发现性能瓶颈，可考虑在服务层做批量查询或引入专门 DTO 减少懒加载次数。
- 逻辑路径构建中对 `isRoot`、`deleted` 做了防御，避免展示已删除目录或异常路径。

3. 兼容性

- 新增字段对现有前端代码是向后兼容的（只添加，不移除原字段）；
- 旧版本前端在不使用 `folderPath` 的情况下也不会受到影响。

## 六、小结

本次实现通过在 `File` 实体中增加 `folderPath` 计算属性，为 `/files/list` 接口补充了文件位置（目录路径）信息，从而使新预览页 `/file-view/:id` 中的“位置”字段能够展示真实路径，而不再是单纯占位文案。该改动没有修改既有接口 URL 与核心业务逻辑，为后续在更多页面展示文件位置信息奠定了基础。
