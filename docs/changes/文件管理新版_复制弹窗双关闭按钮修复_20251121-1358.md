# 文件管理新版复制弹窗双关闭按钮修复（2025-11-21 13:58）

## 问题成因
- “移动/复制”弹窗使用了 Element Plus 的 `el-dialog`，组件默认会在右上角渲染自带关闭按钮。
- 组件模板中又通过 `#header` 插槽加入了一颗自定义的关闭按钮，导致同一对话框出现两个关闭入口（一个来自框架默认，另一个来自自定义）。

## 排查过程与历史
- 定位到 `frontend/src/views/files/Explorer.vue` 中的 `moveCopyDialog` 定义，发现通过 `#header="{ close }"` 自定义了标题与关闭按钮。
- 对照 Element Plus 文档确认：即使自定义 header，默认右上角的关闭按钮依然渲染；因此当前实现的自定义关闭按钮与默认关闭按钮叠加。
- 结合用户需求“只保留最外面的哪一个”，可判定应去掉自定义按钮，保留框架默认关闭按钮即可。

## 修复建议
1. 移除 header 插槽内的自定义关闭按钮，维持默认关闭按钮，避免重复。
2. 保留原有标题与交互逻辑，确保关闭行为仍然可用（默认按钮会触发 `before-close` 逻辑并更新 v-model）。

## 实际采取的修复操作
- 删除 `move-copy-dialog` 中 header 插槽里的自定义关闭按钮，仅保留默认的右上角关闭按钮，其他逻辑不变。

## 验证建议
- 打开 `/files-explorer`，触发任一“移动/复制”弹窗：
  - 只看到右上角单个关闭按钮。
  - 点击关闭按钮，弹窗正常关闭，状态不残留。
  - 复制/移动提交流程不受影响，可正常提交并关闭。

## 风险与影响面
- 仅移除重复按钮，不影响提交、取消、标题展示及其他样式，风险很低。
- 如后续需要自定义 header 布局，可在保持单一关闭入口的前提下再行设计。
