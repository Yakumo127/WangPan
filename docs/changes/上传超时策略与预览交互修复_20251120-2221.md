# 上传超时策略与预览交互修复（2025-11-20 22:21）

## 问题成因
- 上传接口超时：新版上传队列与老版上传接口仍沿用 Axios 默认 10s/固定 300s，未按文件大小动态设定，超过 30MB 或 300MB 的文件在普通网络下容易因超时失败。
- 预览交互：新版资源管理器单击文件无法触发预览，图片分支仅跳转但未真正预览，新版预览页也缺少图片渲染分支。
- 分片暂停：分片上传过程中用户主动暂停/取消会被当作失败计入重试计数，多次操作后可能触达重试上限异常失败。
- 控制台告警：旧版列表页上传进度条向 Element Plus 传入空字符串状态，仍产生告警。

## 排查过程与历史
- 结合 docs/changes 与上线记录，确认上传超时未实现“按文件大小/速度估算”的策略，默认 10s/300s 不足以覆盖大文件。
- 复查 Explorer 单击事件与 `PreviewNew.vue`，发现文件单击未接入预览，且预览页仅处理视频/文本/PDF/Office，图片走 iframe 无法保证渲染。
- 阅读 `useUploadQueue` 分片上传 catch 逻辑，Abort/暂停与真实失败共用计数，反复暂停会累加重试计数。
- 在 List.vue 中确认进度条 `status` 传空字符串，Element Plus 仍提示非法值。

## 修复建议
- 在后端新增上传超时策略配置（auto/manual），前端读取后按区间/文件大小计算 axios 超时；提供系统设置入口便于管理员调整，普通用户通过公共接口获取配置。
- Explorer 单击文件即进入预览，预览页补充图片渲染分支，统一走新版预览路由。
- 分片上传对 Abort/暂停不计入重试，避免误判失败。
- 进度条状态传 `undefined` 以消除告警。

## 实际修复操作
- 后端新增上传超时配置键、读写接口：
  - `SystemSettingService` 增加 `upload.timeout.mode|seconds`，提供 getter/setter。
  - `AdminSystemController` 新增 `/admin/settings/upload-timeout` GET/PUT。
  - `FileController` 新增 `/files/upload-timeout-config` 供普通用户读取。
- 前端配置与策略应用：
  - `System.vue` “基础设置”新增“上传接口超时设置”卡片，可选自动/手动（1~7200 秒），自动规则：0-30MB 150s，30-300MB 700s，大于 300MB 按大小/2MB/s + 180s 缓冲；调用新接口保存/重置。
  - `api/system.js`、`api/file.js` 新增对应接口。
  - 上传逻辑（新上传队列与旧版列表）获取配置并按规则计算 timeout，直传/分片/合并均应用；上传 service/API 支持自定义 timeout。
  - 分片暂停/取消的 Abort 不再累加重试计数。
- 预览/交互修复：
  - Explorer 单击文件直接跳转新版预览页。
  - `PreviewNew.vue` 补充图片类型识别与 `<img>` 渲染。
  - 旧版列表进度条 status 使用 `undefined` 以消除告警。

## 影响范围
- 上传：新旧上传入口的超时配置、恢复/暂停逻辑；需在真实环境验证大文件上传。
- 预览：Explorer 单击预览和新版预览页图片展示。
- 管理端：基础设置 Tab 新增上传超时卡片。
