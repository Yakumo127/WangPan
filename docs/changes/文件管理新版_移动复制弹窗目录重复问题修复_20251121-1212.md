# 文件管理新版移动/复制弹窗目录重复问题修复（2025-11-21 12:12）

## 问题现象
- 打开新版文件管理的“移动/复制”弹窗时，文件夹树出现多次重复的文件夹名称，未按预期从根目录开始展示实际目录结构。
- 同时伴随 500 报错，后端日志出现 `Type definition error: [simple type, class org.hibernate.proxy.pojo.bytebuddy.ByteBuddyInterceptor]`，导致列表与创建目录异常。

## 原因分析
- `/api/folders/list` 直接返回 `Folder` 实体列表，实体包含 `parent/children/files` 等懒加载关联，序列化时触发 Hibernate 代理（ByteBuddyInterceptor），Jackson 无法处理代理对象导致 500。
- 前端弹窗树组件拿到异常/残缺的响应数据后重复渲染节点，表现为多遍同名目录。

## 修复方案
- 对外返回瘦身 DTO，避免序列化懒加载代理：
  - 添加 `FolderSimpleDto`（仅保留 id/name/parentId/createTime）。
  - `getUserFolders`、`createFolder` 等接口改为返回 DTO 列表/对象，去除代理字段。
- 保持原有业务逻辑不变，确保根目录与子目录按 parentId 查询正常返回。

## 实际改动
- `backend/src/main/java/com/filemanager/dto/FolderSimpleDto.java`：新增文件夹简化 DTO。
- `backend/src/main/java/com/filemanager/controller/FolderController.java`：`getUserFolders` 和 `createFolder` 返回 DTO（映射 id/name/parentId/createTime），避免直接序列化实体。

## 影响评估
- 接口返回格式从实体变为简化字段（前端列表/树仅用 id/name/parentId，不受影响），序列化代理错误消除，目录树恢复正常。
- 业务逻辑、数据库结构不变，风险可控。***
