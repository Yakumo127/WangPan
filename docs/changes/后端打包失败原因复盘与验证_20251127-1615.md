# 后端打包失败原因复盘与验证（2025-11-27 16:15）

## 问题成因
- 近期改动在 `backend/src/main/java/com/filemanager/controller/FileController.java` 的移动接口中误用了未定义变量 `body`，编译时报 “找不到符号 body”，导致 Maven 打包失败；修正为 `request.get(\"newName\")` 后即可恢复。
- 改动前接口未引入该变量名错误，因而能正常编译；错误改动直接引入编译期异常，打包即刻失败。

## 排查过程与历史
- 查阅 `docs/文档变更总记录.md` 及 `docs/changes/文件管理后台_文件移动接口未定义变量修复_20251121-0954.md`，定位到移动接口变量名错误的历史记录。
- 核对当前 `FileController` 对应行（约 1426-1445 行），确认已改为 `request.get(\"newName\")`，不存在未定义变量。
- 在 `backend` 目录分别执行 `mvn -q -DskipTests package` 与 `mvn -q package`，两次均成功完成，验证打包已恢复。

## 修复建议
- 后续在控制器层新增参数时，统一复用方法入参命名，避免同一方法内混用不存在的局部变量。
- 在提交前引入最小化的编译检查（`mvn -q -DskipTests package`）作为 pre-commit 步骤，及时发现编译期错误。
- 变更控制器接口后同步补充单元/集成测试，以覆盖基本请求体解析与权限校验逻辑。

## 实际采取的修复操作
- 无新增代码改动，确认现有修复已到位：`FileController` 移动接口使用 `request.get(\"newName\")`。
