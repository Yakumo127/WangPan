# 文件管理新版移动弹窗请求去重实现（2025-11-21 13:26）

## 变更背景
- 一次点击“移动/复制”即触发约 10 次 `GET /api/folders/list`，重复请求来自列表刷新、弹窗初始化与树形懒加载缺乏缓存复用。
- 多轮尝试主要聚焦去重节点，但根请求仍重复，需统一梳理目录数据获取与缓存策略。

## 改动概述
1. **目录数据统一缓存**
   - 新增 `fetchFolderList` / `invalidateFolderCache` 工具：利用 `folderCache + folderLoading` 维护 parentId → 数据/Promise 映射，默认共享缓存，必要时 `force` 拉新数据。
   - `loadEntries` 改为调用 `fetchFolderList`，同时用 `dedupeFolders` 保证列表数据无重复。
2. **移动弹窗树复用列表数据**
   - `loadFolderTreeRoot` 直接消费缓存的根节点数据（首次打开若无缓存则自动请求），不再在打开弹窗时重置缓存。
   - 懒加载 `loadFolderChildren` 统一走 `fetchFolderList`，避免并发命中同一 parentId。
3. **目录变更后的缓存同步**
   - 新建、重命名、删除、移动/复制等操作成功后调用 `invalidateFolderCache`，并针对移动/复制附加目标/来源父级，确保树形下次展开即获取最新结构。

## 验证步骤
- 手动打开 `/files-explorer`，观察加载阶段仅出现 1 次 `GET /api/folders/list`。
- 点击任意“移动”按钮，观察网络面板只新增 1 次根目录请求；展开任意节点，仅在首次展开时出现对应 parentId 的请求。
- 对目录执行创建、重命名、移动，确认树形列表能在下一次打开时展示更新后的名称/层级。

## 风险评估
- 目录缓存位于前端组件内，失效策略依赖显式调用；已在所有涉及目录结构变更的操作中补齐失效逻辑，风险可控。
- 当多个标签页并行操作时，未实时广播缓存更新，但每次打开弹窗都会重新命中缓存/请求，短期可接受。
