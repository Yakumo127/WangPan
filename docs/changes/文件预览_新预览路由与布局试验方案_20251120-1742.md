# 文件预览：新预览路由与布局试验方案（2025-11-20 17:42）

## 一、需求背景

- 现有预览方案：
  - 图片：在文件列表页通过对话框预览；
  - 其他可预览文件：跳转到 `/preview/:id` 使用现有 `Preview.vue` 页面进行预览。
- 新需求：
  - 用户希望尝试一个类似 Seafile 预览页的布局（顶部“系统名称 + 文件名”，右上操作按钮，主体分为信息区 + 预览区）；
  - **暂不修改现有预览逻辑**，而是新增一套“新版预览路由 + 页面 + 入口按钮”用于试验效果；
  - 仅对非图片文件提供新预览入口，图片仍使用现有对话框预览；
  - 新预览页右上角去掉“分享”“客户端打开”这类按钮，仅保留基础操作（例如返回、下载等）。

目标：增加一条新的预览路由和页面，通过文件列表中的“预览”按钮进入新页面，观察并迭代新布局的体验，同时保持旧页面 `/preview/:id` 行为不变。

## 二、总体设计

1. 新增路由
- 路由路径：`/file-view/:id`（示例）；
- 路由名称：`FilePreviewNew`；
- 组件：`src/views/files/PreviewNew.vue`；
- meta：
  - `title: '文件预览（新版）'`；
  - `requiresAuth: true`（与其他业务路由一致）。

2. 新预览页面布局（PreviewNew.vue）

新页面仍在 `layout/index.vue` 的主内容区域内渲染，整体布局为：

- 顶部预览头部区域（页面内部头部）：
  - 左侧：
    - 固定文案：“企业文件管理系统 - {{ 文件名 }}”；
  - 右侧操作按钮（暂定）：
    - “返回文件列表”；
    - “下载”；
    - （后续可视需要增加更多按钮，但不包括“分享”“客户端打开”）。

- 主体区域：
  - 左侧文件信息栏（窄列）：
    - 标题：“文件信息”；
    - 字段（初版可仅展示基础信息，如名称，后续可扩展大小、类型、时间等）；
  - 右侧预览内容区（宽列）：
    - 根据文件类型展示：
      - 文本（txt/log/md）：`<pre>` 文本预览；
      - 视频（mp4）：`<video controls :src="blobUrl">` 预览；
      - PDF / Office / 其他二进制：`<iframe :src="blobUrl">` 交给浏览器处理；
    - loading 与错误提示行为与现有 `Preview.vue` 一致。

3. 列表页新增“预览”按钮

- 在 `List.vue` 的“操作”列中，为非图片文件添加新的“预览”按钮：
  - 仅当文件扩展名不在 `['jpg', 'jpeg', 'png']` 中时显示；
  - 点击后跳转到新路由 `/file-view/:id`，并通过 `query` 传入文件名：
    - `router.push({ name: 'FilePreviewNew', params: { id: file.id }, query: { name: file.originalFilename || file.name || '' } })`；
  - 原有“点击文件名触发预览”的行为保持不变：
    - 图片仍打开对话框；
    - 其他可预览文件仍跳转到旧路由 `/preview/:id`，使用旧页面逻辑。

## 三、前端实现细节

### 1. 路由新增

修改 `frontend/src/router/index.js`：

```js
{
  path: '/file-view/:id',
  name: 'FilePreviewNew',
  component: () => import('@/views/files/PreviewNew.vue'),
  meta: { title: '文件预览（新版）', requiresAuth: true }
},
```

保持现有 `/preview/:id` 路由不变。

### 2. 新预览页组件 PreviewNew.vue

1. 路由参数与状态

- 从路由中获取：
  - `fileId = route.params.id`；
  - `filename = route.query.name || ''`；
- 状态：
  - `loading`：加载中标记；
  - `error`：错误信息；  
  - `blobUrl`：预览用 blob URL；
  - `textContent`：文本类文件内容；
  - `viewerType`：`'text' | 'video' | 'pdf' | 'office' | 'unknown'` 等。

2. 数据加载逻辑

- 使用已有 API：
  - `previewFile(id)` 从 `/files/{id}/preview` 获取 Blob（`responseType: 'blob'`）；
  - 类型判断逻辑沿用现有 `Preview.vue` 的实现：
    - 综合响应头 `Content-Type` 与扩展名：
      - `application/pdf` → `'pdf'`；
      - `video/*` 或扩展名 `mp4` → `'video'`；
      - `text/*` 或扩展名 `txt/log/md` → `'text'`；
      - `doc/docx/ppt/pptx` → `'office'`；
  - 文本类型：`blob.text()` → `textContent`；
  - 其他类型：
    - 对于 PDF：必要时强制包装为 `application/pdf` 的 Blob，以优化浏览器预览效果；
    - 统一通过 `URL.createObjectURL(blob)` 生成 `blobUrl`。

3. 顶部与主体模板结构

示意结构：

```vue
<template>
  <div class="file-preview-page">
    <div class="file-preview-header">
      <div class="header-left">
        <span class="system-name">企业文件管理系统</span>
        <span class="separator">-</span>
        <span class="file-name">{{ filename }}</span>
      </div>
      <div class="header-actions">
        <el-button size="small" @click="goBack">
          <el-icon><ArrowLeft /></el-icon> 返回文件列表
        </el-button>
        <el-button size="small" @click="downloadFile">
          <el-icon><Download /></el-icon> 下载
        </el-button>
      </div>
    </div>

    <div class="file-preview-body" v-loading="loading">
      <template v-if="error">
        <!-- 错误提示 -->
      </template>
      <template v-else>
        <div class="file-preview-layout">
          <aside class="file-preview-sidebar">
            <!-- 文件信息（名称等，后续可扩展） -->
          </aside>
          <main class="file-preview-content">
            <!-- 根据 viewerType 展示 video / pre / iframe -->
          </main>
        </div>
      </template>
    </div>
  </div>
</template>
```

### 3. 列表页新增“预览”按钮

修改 `frontend/src/views/files/List.vue` 中“操作”列：

1. 引入预览图标（可选）：

```js
import { View, ... } from '@element-plus/icons-vue'
```

2. 在操作列模板中添加按钮（仅非图片文件展示）：

```vue
<el-button-group>
  <el-button size="small" @click="downloadFile(row)">
    <el-icon><Download /></el-icon>
    下载
  </el-button>
  <el-button
    size="small"
    @click="openNewPreview(row)"
    v-if="!isImageFile(row)"
  >
    <el-icon><View /></el-icon>
    预览
  </el-button>
  <!-- 原有重命名/删除按钮保持不变 -->
</el-button-group>
```

3. 新增判断与跳转逻辑：

```js
const isImageFile = (file) => {
  const ext = getFileExt(file)
  return ['jpg', 'jpeg', 'png'].includes(ext)
}

const openNewPreview = (file) => {
  router.push({
    name: 'FilePreviewNew',
    params: { id: file.id },
    query: { name: file.originalFilename || file.name || '' }
  })
}
```

原有 `onFileNameClick` 行为保持不变，不受影响。

## 四、影响评估

1. 对现有功能的影响
- 现有预览行为完全保留：
  - 图片：对话框预览；
  - 其他可预览文件：仍使用旧路由 `/preview/:id` 与旧页面；
- 新路由和新页面完全独立，只通过新增的“预览”按钮进入，不影响现有用户使用路径。

2. 试验性质
- 新预览页用于试验三栏布局、顶部标题和操作按钮的排布；
- 若体验不佳，可以随时移除该路由与按钮，不会波及旧逻辑；
- 若体验良好，可在后续迭代中逐步考虑：
  - 将文件名点击行为切换到新预览页；
  - 甚至替换旧 `/preview/:id` 页面。

3. 风险
- 改动集中在前端：
  - 新增一个视图组件、一个路由条目、一个按钮和对应的跳转逻辑；
  - 后端接口全部复用既有 `/files/{id}/preview` 与下载 URL 接口；
- 风险主要是新页面自身的布局与渲染问题，不会影响上传、下载、列表等既有功能。

## 五、小结

本方案在不触碰现有预览实现的前提下，新增了一条“新版预览路由 + 页面 + 按钮入口”，便于在真实环境中试验 Seafile 风格的预览布局。后续可根据使用反馈决定是否逐步迁移现有预览行为至新布局，或对新布局进行进一步调整。
