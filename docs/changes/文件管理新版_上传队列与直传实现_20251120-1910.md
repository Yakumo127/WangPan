# 文件管理（新版）上传队列与直传实现（2025-11-20 19:10）

## 一、变更背景

在《文件管理（新版）上传功能升级设计_20251120-1858》中已经对“文件管理（新版）”中上传功能的目标、架构与流程做了整体规划。当前阶段的目标是：

1. 在不影响现有旧上传功能的前提下，为新版文件管理页面（Explorer）接入一套基础的上传队列实现；
2. 落地“秒传检查 + 直传小文件”完整闭环：
   - 支持多文件选择与拖拽到当前目录上传；
   - 上传过程有队列展示、状态与进度可视化；
   - 秒传命中时无需实际上传数据；
3. 为后续分片上传与断点续传实现预留接口与结构。

本次变更仅在前端完成上传队列骨架与 Explorer 集成，不修改后端代码。

```js
export function directUpload({ file, folderId, filename, onUploadProgress, cancelToken }) {
  const formData = new FormData()
  formData.append('file', file)
  if (folderId != null) formData.append('folderId', folderId)
  if (filename) formData.append('filename', filename)
  return request({
    url: '/files/upload',
    method: 'post',
    data: formData,
    headers: { 'Content-Type': 'multipart/form-data' },
    onUploadProgress,
    cancelToken
  })
}
```

### 2.2 新增文件哈希工具 `fileHash.js`

文件：`frontend/src/utils/fileHash.js`

职责：

- 提供基础的 SHA-256 计算能力，供上传队列在“秒传检查”前使用：

```js
export async function computeFileSha256(file) {
  if (!file) throw new Error('文件为空')
  if (!window.crypto || !window.crypto.subtle) {
    throw new Error('当前环境不支持加密 API，无法计算哈希')
  }
  const buffer = await file.arrayBuffer()
  const hashBuffer = await window.crypto.subtle.digest('SHA-256', buffer)
  const hashArray = Array.from(new Uint8Array(hashBuffer))
  const hashHex = hashArray.map((b) => b.toString(16).padStart(2, '0')).join('')
  return hashHex
}
```

说明：

- 当前实现为“整体读入 + 一次性计算”，足以满足中小文件场景需求；
- 对于极大文件后续可按设计文档升级为分块流式计算，避免占用过多内存。

### 2.3 新增上传队列组合函数 `useUploadQueue.js`

文件：`frontend/src/composables/useUploadQueue.js`

职责：

- 管理上传队列与任务状态机；
- 编排“计算哈希 → 秒传检查 → 直传上传”的基础流程；
- 暴露给页面使用的队列与控制函数。

关键设计：

1. 队列状态：

```js
const uploadQueue = ref([])
const activeUploadsCount = ref(0)

const hasRunningTasks = computed(() =>
  uploadQueue.value.some((t) => t.status === 'hashing' || t.status === 'checking_fast' || t.status === 'uploading')
)
```

2. 入队接口：

```js
const enqueueFiles = (files, folderId) => {
  const fid = folderId != null ? folderId : getCurrentFolderId()
  const list = Array.from(files || [])
  if (!list.length) return
  const now = Date.now()
  for (const file of list) {
    const task = {
      id: `${now}-${Math.random().toString(16).slice(2)}`,
      file,
      name: file.name,
      size: file.size,
      folderId: fid,
      hash: null,
      status: 'pending',
      progress: 0,
      uploadedBytes: 0,
      errorMessage: '',
      isFastUploaded: false,
      useChunks: false,
      createdAt: now,
      updatedAt: now
    }
    uploadQueue.value.push(task)
  }
  schedule()
}
```

3. 调度与任务执行：

- 通过 `MAX_CONCURRENT_FILES = 2` 控制同时上传文件任务数；
- `schedule()` 从队列中挑选 `pending` 任务启动；
- `startTask(task)` 执行完整链路：

```js
// 1. 计算哈希
updateTask(task, { status: 'hashing', progress: 0 })
const hash = await computeFileSha256(task.file)
updateTask(task, { hash, status: 'checking_fast' })

// 2. 秒传检查
try {
  const res = await checkFastUpload({ hash, size: task.size, folderId: task.folderId })
  if (res && res.exists) {
    updateTask(task, {
      status: 'completed',
      isFastUploaded: true,
      progress: 100,
      uploadedBytes: task.size
    })
    onTaskCompleted()
    return
  }
} catch (e) {
  console.warn('秒传检查失败，回退为普通上传:', e)
}

// 3. 直传
updateTask(task, { status: 'uploading', progress: 0 })
await directUpload({
  file: task.file,
  folderId: task.folderId,
  filename: task.name,
  onUploadProgress: (evt) => { ...更新进度... }
})
updateTask(task, { status: 'completed', progress: 100, uploadedBytes: task.size })
onTaskCompleted()
```

- 错误处理：捕获异常，标记任务为 `failed`，记录 `errorMessage` 并通过 `ElMessage` 提示用户。

4. 暂停/恢复/取消占位：

- 当前阶段仅对外暴露占位实现（提示“后续迭代提供”），不真正中断 axios 请求；
- 重试功能已实现，允许对 `failed` 任务重新入队。

对外暴露接口：

```js

  hasRunningTasks,
  enqueueFiles,
```

## 四、影响评估

1. 对现有功能的影响：
   - 仅修改了 `Explorer.vue`，未触碰旧文件管理页面与旧上传逻辑；
   - 新增的上传功能完全挂在“文件管理（新版）”之下，不影响原有 `/files` 页面。

2. 性能与体验：
   - 同时上传的文件数限制为 2，避免一次性对后端造成过大压力；
   - 哈希计算采用一次性读入方式，对超大文件可能有性能压力，后续可优化；
   - 状态与进度展示以表格 + 进度条形式，简洁清晰。

3. 安全与策略：
   - 上传策略、配额与权限检查仍由后端接口负责；
   - 前端不绕过任何后端限制，仅负责调用与展示。

本次变更为后续“分片上传 + 断点续传”实现打下基础，实现了“秒传检查 + 直传上传”的完整闭环，并与文件管理（新版）的当前目录管理集成。
