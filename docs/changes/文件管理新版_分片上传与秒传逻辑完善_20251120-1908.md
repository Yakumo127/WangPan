# 文件管理（新版）分片上传与秒传逻辑完善（2025-11-20 19:08）

## 一、变更背景

在上一轮变更中，我们已经为“文件管理（新版）”接入了上传队列与基础直传能力，并实现了前端哈希计算和秒传检查占位逻辑。但当时：

- 秒传接口使用的是设计阶段的临时 URL `/files/fast-upload/check`，与后端现有实现不一致；
- 分片上传相关接口仅在前端预留了封装，但上传队列实际仍只支持直传，不支持真正的大文件分片上传与断点续传；
- 暂停/恢复/取消上传仅为占位提示，未提供实质控制。

本次变更的目标是：

1. 对齐后端已经存在的“秒传 + 快速创建”接口（`/files/exists-global` + `/files/quick-create`），实现真正的秒传创建行为；
2. 在上传队列中落地大文件分片上传与断点续传逻辑，使用后端已经提供的 `/files/chunk`、`/files/chunk/status`、`/files/merge` 接口；
3. 为上传队列补充基本的暂停/恢复/取消控制，使用户可以对正在运行的任务进行管理。

## 三、上传服务层调整 `uploadService.js`

文件：`frontend/src/services/uploadService.js`

### 3.1 秒传封装：对接 exists-global + quick-create

原先的 `checkFastUpload` 仅是临时 URL 占位，本次改造为：

```js
// 秒传检查 + 快速创建文件（基于已有 Blob）
// 返回结构约定：{ exists: boolean, fileId?: number }
export async function checkFastUpload({ hash, filename, folderId, parentId }) {
  // 1. 先检查 Blob 是否存在（全局）
  const existsResp = await request({
    url: '/files/exists-global',
    method: 'post',
    data: { fileHash: hash }
  })
  if (!existsResp || !existsResp.exists) {
    return { exists: false }
  }
  // 2. Blob 已存在，调用 quick-create 在当前目录创建文件或新版本
  const qcResp = await request({
    url: '/files/quick-create',
    method: 'post',
    data: {
      fileHash: hash,
      filename,
      folderId: folderId ?? null,
      parentId: parentId ?? null
    }
  })
  return {
    exists: true,
    fileId: qcResp && qcResp.fileId
  }
}
```

行为：

- 当指定哈希在全局 Blob 中存在时，将直接在当前 `folderId` 下创建文件（或 parentId 下创建新版本），实现真正的“秒传创建”；
- 若 Blob 不存在，则返回 `{ exists: false }`，上传队列会回退为正常上传流程。

### 4.4 分片上传与断点续传实现

核心逻辑在 `uploadByChunks(task)` 中：

1. 初始化分片：

```js
const totalChunks = Math.max(1, Math.ceil(task.size / CHUNK_SIZE))
const chunks = []
for (let i = 1; i <= totalChunks; i++) {
  chunks.push({
    index: i,
    uploaded: false,
    uploading: false,
    retryCount: 0,
    errorMessage: ''
  })
}
updateTask(task, {
  status: 'uploading',
  totalChunks,
  chunks,
  uploadedBytes: 0,
  progress: 0
})
```

2. 断点续传：查询已上传分片：

```js
try {
  const status = await getChunkStatus({ hash: task.hash, total: totalChunks })
  const uploadedIndexes = Array.isArray(status?.uploaded) ? status.uploaded : []
  if (uploadedIndexes.length > 0) {
    let doneBytes = 0
    for (const idx of uploadedIndexes) {
      const chunk = chunks.find(c => c.index === idx)
      if (chunk) {
        chunk.uploaded = true
        const start = (idx - 1) * CHUNK_SIZE
        const end = Math.min(task.size, idx * CHUNK_SIZE)
        doneBytes += (end - start)
      }
    }
    updateTask(task, {
      uploadedBytes: doneBytes,
      progress: Math.round((doneBytes / task.size) * 100)
    })
  }
} catch (e) {
  console.warn('查询分片状态失败，按全新上传处理:', e)
}
```

3. 分片上传调度：

```js
const doUploadChunk = async (chunkState) => {
  if (chunkState.uploaded) return
  if (chunkState.uploading) return
  if (chunkState.retryCount > MAX_CHUNK_RETRY) {
    throw new Error(`分片 #${chunkState.index} 重试次数超限`)
  }
  chunkState.uploading = true
  try {
    const start = (chunkState.index - 1) * CHUNK_SIZE
    const end = Math.min(task.size, chunkState.index * CHUNK_SIZE)
    const blob = task.file.slice(start, end)
    await uploadChunk({
      hash: task.hash,
      index: chunkState.index,
      total: totalChunks,
      chunk: blob
    })
    chunkState.uploaded = true
    chunkState.errorMessage = ''
    const uploadedBytes = (task.chunks || []).reduce((sum, c) => {
      if (!c.uploaded) return sum
      const cs = (c.index === totalChunks)
        ? (task.size - CHUNK_SIZE * (totalChunks - 1))
        : CHUNK_SIZE
      return sum + cs
    }, 0)
    updateTask(task, {
      uploadedBytes,
      progress: Math.round((uploadedBytes / task.size) * 100)
    })
  } catch (e) {
    chunkState.retryCount += 1
    chunkState.errorMessage = e?.message || '分片上传失败'
    console.error(`分片上传失败 #${chunkState.index}:`, e)
    if (chunkState.retryCount > MAX_CHUNK_RETRY) {
      throw e
    }
  } finally {
    chunkState.uploading = false
  }
}

const runChunks = async () => {
  while (true) {
    const pending = (task.chunks || []).filter(c => !c.uploaded && !c.uploading)
    if (!pending.length) break
    const batch = pending.slice(0, MAX_CHUNK_CONCURRENCY)
    await Promise.all(batch.map(c => doUploadChunk(c)))
  }
}

await runChunks()
```

### 4.5 暂停/恢复/取消控制

在队列中增加简单的暂停/恢复/取消实现：

```js
const pauseTask = (taskId) => {
  const task = uploadQueue.value.find((t) => t.id === taskId)
  if (!task) return
  if (task.status === 'uploading' || task.status === 'hashing' || task.status === 'checking_fast') {
    updateTask(task, { status: 'paused' })
    ElMessage.info(`已标记暂停：${task.name}（当前分片会自然完成，后续不再继续）`)
  }
}

const resumeTask = (taskId) => {
  const task = uploadQueue.value.find((t) => t.id === taskId)
  if (!task) return
  if (task.status === 'paused') {
    updateTask(task, { status: 'pending' })
    schedule()
  }
}

const cancelTask = (taskId) => {
  const idx = uploadQueue.value.findIndex((t) => t.id === taskId)
  if (idx === -1) return
  const task = uploadQueue.value[idx]
  if (task.status === 'completed') return
  uploadQueue.value.splice(idx, 1)
}
```

说明：

- 暂停本质上是改变任务状态为 `paused`，使调度器不再选择该任务继续上传；当前正在上传的分片会自然完成但不继续后续分片；
- 恢复则将状态改为 `pending`，重新纳入调度；
- 取消会从队列中直接移除任务（不通知后端清理分片，后端已有分片可根据 TTL/清理任务处理）。

## 六、行为与影响评估

1. 秒传行为：
   - 前端通过 SHA-256 计算 hash 后调用 `/files/exists-global`；
   - 若 Blob 存在，则通过 `/files/quick-create` 在当前目录创建文件，队列中该任务直接标记为“秒传完成”，无需实际上传文件内容；
   - 若 Blob 不存在，自动退回直传/分片上传流程。

2. 大文件上传行为：
   - 当文件大小 ≥ 10MB 时，自动使用分片上传；
   - 支持在上传前查询已存在分片并补传缺失分片，实现基本断点续传能力；
   - 分片上传过程中对单个分片提供有限重试（默认 3 次），超过后整个任务失败；
   - 全部分片成功后自动调用合并接口，保证文件完整入库。

3. 任务控制与用户体验：
   - 用户可以在队列中对单个任务进行暂停、继续与取消操作；
   - 队列显示更丰富的状态（hashing、checking_fast、uploading、merging 等），有助于问题排查；
   - 上传成功仍会触发 Explorer 刷新当前目录，用户能即时看到新文件。

4. 兼容性：
   - 未修改后端接口，仅对前端调用方式进行对齐与增强；
   - 对小文件直传逻辑与已有上传策略/配额校验保持兼容；
   - 旧文件管理页面与旧上传逻辑不受本次变更影响。

本次变更至此使得“文件管理（新版）”在前端层面已经具备：秒传、直传、大文件分片上传、基本断点续传以及任务暂停/恢复/取消等完整能力，后续如需进一步增强（本地持久化队列、前端更细粒度错误提示等）可以在此基础上迭代。
