## 二、后端具体改动

### 2.1 SystemSettingService：预览后缀配置

文件：`backend/src/main/java/com/filemanager/service/SystemSettingService.java`

1. 新增配置键常量：
   - `public static final String KEY_PREVIEW_ALLOWED_SUFFIXES = "file.preview.allowed.suffixes";`

2. 新增读取方法：
   - `public java.util.List<String> getPreviewAllowedSuffixes()`：
     - 从 `system_config` 读取 `KEY_PREVIEW_ALLOWED_SUFFIXES`；
     - 如为空，则使用默认值：
       - `doc,docx,ppt,pptx,pdf,txt,mp4,jpg,jpeg,png`；
     - 将值按逗号拆分，去空格、转小写，去掉前置点号，过滤非法后缀，仅保留 `[a-z0-9]+`，并去重。

3. 新增写入方法：
   - `public void setPreviewAllowedSuffixes(List<String> suffixes, User updatedBy)`：
     - 将传入后缀统一处理（trim、小写、去点），过滤非法字符，只保留 `[a-z0-9]+`；
     - 使用 `setString` 将列表 join 为逗号分隔字符串写入 `system_config`；
     - 通过 `@AuditedOperation` 记录“预览配置更新”的审计日志。

### 2.2 AdminSystemController：预览配置管理接口

文件：`backend/src/main/java/com/filemanager/controller/AdminSystemController.java`

1. 获取配置：
   - `GET /api/admin/settings/preview-config`
   - 返回：
     ```json
     { "allowedSuffixes": ["doc","docx","ppt","pptx","pdf","txt","mp4","jpg","jpeg","png"] }
     ```
   - 数据来自 `systemSettingService.getPreviewAllowedSuffixes()`。

2. 更新配置：
   - `PUT /api/admin/settings/preview-config`
   - 请求体示例：
     ```json
     { "allowedSuffixes": ["pdf","txt","jpg","png","mp4"] }
     ```
   - 逻辑：
     - 从 body 中解析 `allowedSuffixes` 列表，转为字符串列表；
     - 校验非空（至少一个后缀），否则抛出 400；
     - 调用 `systemSettingService.setPreviewAllowedSuffixes(...)` 持久化；
     - 返回更新后的列表。

### 2.3 FileController：预览接口与配置查询

文件：`backend/src/main/java/com/filemanager/controller/FileController.java`

1. 注入 `SystemSettingService`：
   - 增加字段：`private final SystemSettingService systemSettingService;`

2. 预览接口：
   - `GET /api/files/{fileId}/preview`
   - 主要流程：
     1) 从 `SecurityContext` 获取当前用户 username → userId，判断是否管理员（`ROLE_ADMIN`）；  
     2) 管理员使用 `fileService.getFileByIdForAdmin(fileId)` 获取文件；普通用户使用 `fileService.getFileForDownload(fileId, userId)`（权限与下载一致）；  
     3) 解析文件名后缀（小写，不含点），判断是否在 `systemSettingService.getPreviewAllowedSuffixes()` 中；  
     4) 检查文件物理路径存在且可读；  
     5) 通过 `determinePreviewContentType(file, filePath, ext)` 确定合适的 Content-Type（优先扩展名映射，其次文件/探测）；  
     6) 构造 `Content-Disposition: inline` 头部，使用 `StreamingResponseBody` 直接将文件流写出。
   - 审计日志：
     - 失败场景（文件不存在/无权限/类型不允许/物理文件缺失）：
       - 调用 `auditLogService.logFailure(userId, UserLog.ACTION_PREVIEW, RESOURCE_FILE, fileId, filename, "...原因描述...", errorMessage, 耗时)`；
     - 成功场景：
       - 在流式写出完成后调用 `logSuccess` 记录 `ACTION_PREVIEW`。

3. 预览配置查询（普通用户）：
   - `GET /api/files/preview/config`
   - 返回：
     ```json
     { "allowedSuffixes": [...] }
     ```
   - 用于前端用户界面判断某文件是否可预览。

4. Content-Type 解析辅助方法：
   - 新增私有方法 `determinePreviewContentType(File file, Path filePath, String ext)`：
     - 对常见类型（jpg/jpeg/png/gif/webp/pdf/txt/mp4/doc/docx/ppt/pptx）给出固定 Content-Type；
     - 无匹配时回退到 `file.getContentType()` 或 `Files.probeContentType`；
     - 最终默认值为 `application/octet-stream`。

### 2.4 UserLog：新增预览操作类型

文件：`backend/src/main/java/com/filemanager/entity/UserLog.java`

- 新增常量：
  - `public static final String ACTION_PREVIEW = "PREVIEW";`
- 预览成功、失败均使用该 actionType，结合 status=SUCCESS/FAILED 区分。

## 三、前端具体改动

### 3.2 系统设置：预览配置 Tab

文件：`frontend/src/views/admin/System.vue`

1. 新增 Tab：
   - `<el-tab-pane label="预览配置" name="preview">`；
   - 内部使用一个 `el-card` + `el-form`：
     - `previewPolicy.allowedSuffixes` 保存当前配置；
     - 使用 `el-select` 多选 + `allow-create`，允许输入小写后缀（不含点），按回车新增；
     - “恢复默认”按钮：将后缀重置为 `['doc','docx','ppt','pptx','pdf','txt','mp4','jpg','jpeg','png']`；
     - “保存预览配置”按钮：调用 `updatePreviewConfig`，失败时提示。

2. 状态与方法：
   - 新增：
     - `const previewPolicy = ref({ allowedSuffixes: [] })`；
     - `const previewInvalidSuffixes = ref([])`；
     - `onPreviewSuffixesChange(vals)`：归一化后缀并标记非法项；  
     - `resetPreviewPolicyToDefault()`：恢复默认列表；  
     - `savePreviewPolicy()`：调用 API 持久化；
   - 在 `onMounted` 中：
     - 在加载上传策略后，增加一次 `getPreviewConfig()` 调用，将返回的 `allowedSuffixes` 初始化到 `previewPolicy` 中，若失败则保持默认。

### 3.3 文件列表页：单击文件名触发预览

文件：`frontend/src/views/files/List.vue`

1. 表格文件名列：
   - 将原先的静态文件名替换为可点击元素：
     ```vue
     <span
       class="file-name"
       :class="{ clickable: isPreviewable(row) }"
       @click="onFileNameClick(row)"
     >
       {{ row.originalFilename || row.name }}
     </span>
     ```
   - 样式增加 `.file-name.clickable`：蓝色、下划线、pointer。

2. 状态与方法：
   - `previewSuffixes`：从 `getPreviewConfigForUser()` 拉取预览后缀；
   - `getFileExt(file)`：解析扩展名；
   - `isPreviewable(file)`：判断扩展名是否在 `previewSuffixes` 中；
   - `onFileNameClick(file)`：
     - 若不可预览则无动作；
     - 若为图片（jpg/jpeg/png）调用 `previewImage(file)`（弹出对话框预览）；
     - 否则跳转到预览页：
       - `router.push({ name: 'FilePreview', params: { id: file.id }, query: { name: file.originalFilename || file.name || '' } })`。
   - `previewImage(file)`：
     - 调用 `previewFileApi(file.id)` 获取 blob；
     - `URL.createObjectURL(blob)` 生成 `imagePreviewUrl`，打开 `imagePreviewVisible` 对话框进行预览。

3. 生命周期：
   - `onMounted` 中增加 `loadPreviewConfig()`，确保页面加载时获取预览配置。

### 3.4 首页：“最近文件”单击预览

文件：`frontend/src/views/Home.vue`

1. 最近文件列表：
   - 将原本的“点击即下载”改为“点击即尝试预览”：
     ```vue
     <div v-for="file in recentFiles" :key="file.id" class="file-item" @click="onRecentFileClick(file)">
     ```

2. 逻辑：
   - 与文件列表类似，增加：
     - `previewSuffixes`、`getFileExt(file)`、`isPreviewable(file)`；
     - `onRecentFileClick(file)`：
       - 若不可预览则无动作；
       - 若图片 → 跳转到文件页，由文件列表统一处理图片预览；
       - 其他可预览类型 → 跳转到 `FilePreview` 路由，并携带文件名作为 query。
   - 在 `onMounted` 中新增 `loadPreviewConfig()` 调用。

### 3.5 管理员文件页：单击文件名触发预览

2. 状态与方法：

     - `onFileNameClick(file)` 路由跳转到 `FilePreview`。
   - 在 `onMounted` 中调用 `loadPreviewConfig()`（复用普通用户的 `getPreviewConfigForUser`，管理员同样可以获取预览配置）。

### 3.6 预览页：FilePreview

文件：`frontend/src/views/files/Preview.vue`

1. 路由：
   - 在 `frontend/src/router/index.js` 中新增：
     ```js
     {
       path: '/preview/:id',
       name: 'FilePreview',
       component: () => import('@/views/files/Preview.vue'),
       meta: { title: '文件预览', requiresAuth: true }
     }
     ```

2. 组件行为：
   - 从 `route.params.id` 获取 fileId，从 `route.query.name` 获取文件名（用于推断后缀以及展示标题）；
   - 根据扩展名决定 `viewerType`：
     - `pdf` → `pdf`（iframe）；
     - `txt/log/md` → `text`（pre 文本）；
     - `mp4` → `video`；
     - `doc/docx/ppt/pptx` → `office`（iframe）；  
   - `loadPreview()`：
     - 调用 `previewFileApi(fileId)` 获取 blob；
     - 若 `viewerType === 'text'`，使用 `blob.text()` 直接解析并展示；  
     - 其他类型使用 `URL.createObjectURL(blob)` 生成 `blobUrl`，用于 `<iframe>` 或 `<video>`；
   - Header 提供“返回文件列表”按钮。

3. 错误处理：
   - 请求失败时：
     - 在页面中提示“加载预览失败”；  
     - 弹出 `ElMessage.error` 提示；
     - 底层预览接口也会记录预览失败的审计日志。

## 四、验证建议

1. 功能验证：
   - 在系统设置中的“预览配置” Tab 调整后缀列表，确认文件列表与首页最近文件的“可预览字段”随之变化（点击文件名有/无预览）；  
   - 对 `pdf/txt/jpg/png/mp4` 等类型文件：
     - 单击文件名 → 预览（图片弹对话框，其余进入预览页）；  
   - 对 `doc/ppt`：
     - 单击文件名 → 进入预览页，若浏览器支持则在线预览；否则采用浏览器本身行为（可能提示用本地应用打开或下载），系统仍记录为“预览尝试”。

2. 权限与审计验证：
   - 普通用户仅能预览自己的文件，尝试预览他人文件应返回 403，并记录预览失败日志；  
   - 管理员可预览任意文件；  
   - `user_logs` 表中应出现 `ACTION_PREVIEW` 类型的成功/失败记录。

3. 配置验证：
   - 在“预览配置”中移除某后缀（如 `pdf`），刷新页面后对应文件不再可预览（单击文件名无动作），而下载仍通过“下载”按钮正常工作；  
   - 恢复默认后，预览能力恢复。
