# 下载直链与一次性 Token 实施记录（2025-11-20 11:52）

本文记录根据《下载直链与一次性Token设计方案_20251120-1144.md》在后端与前端实际落地实现的过程，包括问题成因回顾、实现范围、关键改动点及后续验证建议，便于后续维护与复盘。

## 一、问题成因回顾（简要）

- 早期实现使用 Axios 直接下载文件（`responseType: 'blob'`），全局超时为 10 秒，大文件在网络较慢时易被 Axios 主动中断，产生 `timeout of 10000ms exceeded` 报错；
- 为规避超时，前端改用 `fetch + Blob + a` 方式绕过 Axios 超时限制，但下载过程由 JS 管理，浏览器不会展示原生下载进度条/下载列表，用户难以感知下载状态；
- 同时，前端需要持有完整 Blob，对于更大文件并不理想；
- 因此，根据设计文档，决定引入“短期有效、单次使用”的下载 Token，生成直链交给浏览器原生下载，兼顾体验与安全。

## 二、本次实现范围

1. **后端：**
   - 新增下载 Token 使用记录实体与仓库，实现“单次使用”限制；
   - 新增 `DownloadTokenService`，负责 Token 生成、签名校验、过期校验与单次使用标记；
   - 在 `FileController` 中新增：
     - 普通用户下载直链接口：`GET /api/files/{fileId}/download-url`；
     - 管理员下载直链接口：`GET /api/files/admin/{fileId}/download-url`；
     - 直链下载入口：`GET /api/files/direct-download?token=...`；
   - 在 `SecurityConfig` 中放行 `/api/files/direct-download`，使其不再依赖 JWT Header；
   - 在 `application.yml` / `application-docker.yml` 中新增 `download.token.*` 配置。

2. **前端：**
   - 在 `frontend/src/api/file.js` 中新增：
     - `getDownloadUrl(id)`：普通用户获取下载直链；
     - `getAdminDownloadUrl(id)`：管理员获取下载直链；
   - 调整三个页面的下载逻辑：
     - 用户文件列表页：`frontend/src/views/files/List.vue`；
     - 首页“最近文件”：`frontend/src/views/Home.vue`；
     - 管理员文件管理页：`frontend/src/views/admin/Files.vue`。
   - 下载行为统一改为：
     - 先请求 download-url，拿到一次性直链；
     - 再通过 `<a href="url">` 触发浏览器原生下载。

## 三、关键实现细节

### 3.1 下载 Token 使用记录实体与仓库

- 新增实体：`backend/src/main/java/com/filemanager/entity/DownloadTokenUsed.java`
  - 对应表名：`download_tokens_used`；
  - 字段：
    - `token_hash`（主键）：存储完整 token 的 SHA-256 十六进制字符串；
    - `used_at`：记录 token 首次被使用的时间；
  - 作用：通过主键唯一约束，实现“单次使用”限制。

- 新增仓库：`backend/src/main/java/com/filemanager/repository/DownloadTokenUsedRepository.java`
  - 接口：`extends JpaRepository<DownloadTokenUsed, String>`；
  - 通过 JPA 与 `ddl-auto: update` 自动创建表结构。

### 3.2 DownloadTokenService 实现

- 文件：`backend/src/main/java/com/filemanager/service/DownloadTokenService.java`
- 主要职责：
  1. **生成 Token：**
     - 普通用户：
       - `generateUserToken(Long fileId, Long userId)`；
     - 管理员：
       - `generateAdminToken(Long fileId, Long userId)`（标记为 admin=true）。
     - Token payload（JSON）格式：
       ```json
       {
         "fileId": 123,
         "userId": 456,
         "admin": false,
         "nonce": "随机字符串",
         "exp": 1732081234567
       }
       ```
     - 使用 `Base64URL(payloadJson)` + `HMAC-SHA256` 生成签名：
       - `token = base64url(payload) + "." + base64url(signature)`。

  2. **解析与校验 Token：**
     - `parseAndValidate(String token)`：
       - 校验格式（两段式结构）；
       - 校验签名是否匹配（HMAC-SHA256）；
       - 解码载荷 JSON，解析 `fileId`、`userId`、`admin`、`nonce`、`exp`；
       - 校验 `exp` 是否大于当前时间，过期则抛出“下载链接已过期”异常。

  3. **单次使用限制：**
     - `assertNotUsedAndMarkUsed(String token)`：
       - 计算 `tokenHash = SHA-256(token)`；
       - 构造 `DownloadTokenUsed` 并调用 `downloadTokenUsedRepository.save(...)`；
       - 若因主键冲突抛出 `DataIntegrityViolationException`，说明 token 已被使用过 → 抛出 `IllegalStateException("下载链接已被使用，请重新发起下载")`。

- 配置绑定：
  - 从配置中读取：
    - `download.token.secret`：专用下载 Token 密钥；
    - `download.token.ttl-seconds`：有效期秒数（当前为 10 秒）；
  - 提供 `getTtlSeconds()` 供控制层计算 `expiresAt`。

### 3.3 SecurityConfig 调整

- 文件：`backend/src/main/java/com/filemanager/config/SecurityConfig.java`
- 调整内容：
  - 在 `.authorizeHttpRequests` 中新增：
    ```java
    .requestMatchers("/api/files/direct-download").permitAll()
    ```
  - 其余 `/api/files/**` 仍要求认证，`/api/files/admin/**` 仍要求 `ROLE_ADMIN`。
  - direct-download 不再依赖 JWT Header，而是完全基于 token 校验。

### 3.4 FileController 新增接口

- 文件：`backend/src/main/java/com/filemanager/controller/FileController.java`
- 新增依赖注入：
  - `private final com.filemanager.service.DownloadTokenService downloadTokenService;`

#### 3.4.1 普通用户：获取下载直链

- 接口：
  - `GET /api/files/{fileId}/download-url`
- 实现要点：
  - 从 SecurityContext 获取当前用户 `username`，再通过 `userService.getUserIdByUsername(username)` 获取 `userId`；
  - 调用 `fileService.getFileForDownload(fileId, userId)` 校验文件存在与归属；
  - 调用 `downloadTokenService.generateUserToken(file.getId(), userId)` 生成普通用户 token；
  - 计算过期时间：
    - `expiresAt = System.currentTimeMillis() + ttlSeconds * 1000`；
  - 组装 URL：
    - `url = "/api/files/direct-download?token=" + token`；
  - 返回 JSON：
    - `{ "url": "...", "expiresAt": 1732xxxxxx }`。

#### 3.4.2 管理员：获取下载直链

- 接口：
  - `GET /api/files/admin/{fileId}/download-url`
- 注解：
  - `@PreAuthorize("hasAuthority('ROLE_ADMIN')")`
- 实现要点：
  - 同样从 SecurityContext 获取管理员 `userId`；
  - 使用 `fileService.getFileByIdForAdmin(fileId)` 校验文件存在；
  - 调用 `downloadTokenService.generateAdminToken(file.getId(), userId)` 生成带 `admin=true` 的 token；
  - 返回结构同普通用户（`url` + `expiresAt`）。

#### 3.4.3 直链下载入口

- 接口：
  - `GET /api/files/direct-download?token=...`
- 实现流程：
  1. 解析并校验 Token：
     - 调用 `downloadTokenService.parseAndValidate(token)`；
     - 若 token 缺失、格式错误、签名不匹配或过期，返回 401/400 类错误。
  2. 用户状态与权限校验：
     - 通过 `userService.getUserById(decoded.userId)` 获取用户并检查：
       - `enabled == true` 且 `locked == false`，否则返回 403；
     - 根据 `decoded.admin` 判断路径：
       - 若 `admin == true`：
         - 校验 `user.role == ADMIN`，否则 403；
         - 使用 `fileService.getFileByIdForAdmin(decoded.fileId)` 获取文件；
       - 否则：
         - 使用 `fileService.getFileForDownload(decoded.fileId, decoded.userId)` 确保文件归属当前用户。
     - 若文件不存在或无权访问，返回 404/403。
  3. 单次使用限制：
     - 调用 `downloadTokenService.assertNotUsedAndMarkUsed(token)`；
     - 若抛出 `IllegalStateException`，返回 410 Gone，提示“下载链接已被使用”。
  4. 构造 SecurityContext（便于复用审计逻辑）：
     - 使用 `userService.loadUserByUsername(user.getUsername())` 构造 `UsernamePasswordAuthenticationToken`，放入 `SecurityContextHolder`；
     - 使后续 `buildDownloadResponse` 内部的审计日志仍能拿到正确的用户 ID。
  5. 流式下载：
     - 调用现有 `buildDownloadResponse(request, fileMeta, filePath)`，复用 Range / ETag / 审计等逻辑；
     - 由浏览器原生处理下载，展示系统级下载进度。

### 3.5 配置新增

- `backend/src/main/resources/application.yml` 与 `application-docker.yml` 中新增：

```yaml
download:
  token:
    secret: enterpriseFileManagerDownloadSecretKey2024
    ttl-seconds: 10
```

说明：

- secret 与 JWT 分离，避免混用登录与下载用途；
- ttl-seconds 按需求设定为 10 秒，满足“点击按钮后浏览器在 10 秒内发起下载请求”的要求。

## 四、验证与风险评估

### 4.1 功能验证建议

1. 普通用户：
   - 登录后访问 `/files` 与首页“最近文件”，尝试下载不同大小文件（包括之前 6MB 问题文件）；
   - 确认浏览器显示原生下载进度条，文件内容正确。

2. 管理员：
   - 在管理页面下载任意用户文件，确认下载成功；
   - 若以普通用户身份尝试访问管理员 download-url 接口，应返回 403。

3. Token 过期与单次使用：
   - 生成 download-url 后等待超过 10 秒再点击链接 → 应返回“链接过期”，前端提示需要重新下载；
   - 同一个 URL 连续刷新两次：
     - 第一次下载成功；
     - 第二次应返回 410（Gone），下载失败。

### 4.2 安全性评估（结合设计文档）

- **链路安全**：需配合 HTTPS，防止 token 在传输过程中被窃听；
- **短期有效**：10 秒 TTL + 单次使用，大幅降低 token 被滥用的风险；
- **权限收紧**：
  - download-url 阶段基于 JWT 做一次权限校验；
  - direct-download 阶段再次基于 token 中的 userId + admin 标记 + 当前用户状态做校验；
- **日志与泄露风险**：
  - 代码中未主动打印 token 明文，但仍建议在运维层面控制 access log 中的 query 内容；
  - 建议在 direct-download 响应中保持 `Cache-Control: no-store`，避免中间缓存；
- **XSS 风险**：
  - 若存在 XSS，则脚本可窃取页面中 download-url；但在 10 秒 TTL + 单次使用约束下，token 价值有限；
  - 根本防线仍是避免 XSS，本次实现将下载链接的“敏感度”降低到相对可控水平。
