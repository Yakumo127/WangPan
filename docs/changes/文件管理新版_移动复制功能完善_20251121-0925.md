# 文件管理新版移动/复制功能完善（2025-11-21 09:25）

## 问题成因
- 新版文件管理仅有“预览”等操作，缺少“移动/复制”入口，无法完成常见文件整理操作。
- 后端暂无文件夹复制接口，文件拷贝和移动也缺少重名处理能力，移动文件夹缺少对子孙目录的递归校验，存在潜在风险。
- 需求要求在操作下拉中提供移动/复制入口，弹窗选择目标目录，遇重名让用户决定是否重命名。

## 排查过程与现状
- 文件接口：`POST /files/{id}/move`、`POST /files/{id}/copy` 仅收 `folderId`，不支持 `newName`，未做重名校验。
- 文件夹接口：仅有 `POST /folders/{id}/move`，无复制接口，移动只防止“移动到自己”，未递归防止移动到子孙。
- 前端 Explorer：操作下拉无移动/复制，缺少目标目录选择弹窗。

## 实际采取的修复动作
- 后端
  - 文件接口：`/files/{id}/move` 和 `/files/{id}/copy` 支持可选 `newName`，目标目录有同名文件会报错，前端可提示后带新名称重试。
  - 文件夹：新增 `POST /folders/{id}/copy`（参数 `targetParentId`、`newName`），递归复制子目录与文件；移动与复制均增加“不可移动/复制到子孙目录”的校验，并对目标目录重名进行校验。
  - 重名校验：文件移动/复制通过仓库查询排除自身 ID，文件夹移动支持改名并排除自身，文件夹复制若同名则报错。
- 前端
  - 新版文件管理列表行的下拉菜单增加“移动”“复制”入口（文件、文件夹各自使用对应接口）。
  - 弹窗“移动/复制 xxx 到”：右上 `X`=取消，内容为懒加载的文件夹树（节点高亮），支持输入新名称（不填沿用原名）。
  - 操作失败且提示同名时，引导用户输入新名称后自动重试。

## 影响评估
- 新增接口与校验会改变后端行为：重名将报冲突而非静默覆盖；移动/复制到子孙目录将被阻止。
- 前端新增操作弹窗与 API 调用，需回归测试文件/文件夹移动、复制、重名场景。
