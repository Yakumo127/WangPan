# 根目录文件整理归档方案与执行记录

## 问题成因
- 根目录包含 `.env`、`docker-compose.yml`、多个脚本及临时文档、日志文件，结构分散且与项目代码/配置混杂，不利于维护和审计。
- 用户要求“文档文件只保存必要保存的，.sh 和 env 不必放在项目根目录”，需将文件分类归档到合适目录。

## 排查过程与现状
- 根目录文件：`.env`、`docker-compose.yml`、`h2-start.sh`、`setup-env.sh`、`simple-start.sh`、`start-project.sh`、`aa_to_csv.py`、临时 Markdown（`A1111111.md`、`A123GENTS.md`、`BACKUP清单.md`）、日志（`backend.log`、`frontend.log`）等。
- 现有目录：`config/`（已有配置与 Docker 相关文件）、`scripts/`（存在但未统一承载所有脚本）、`docs/`（存放正式文档）、`backend/`、`frontend/`、`database/`。

## 整理方案
- 配置类：将 `.env`、`docker-compose.yml` 归档到 `config/`，根目录不再保留同名文件。
- 脚本类：将所有 `.sh` 脚本及辅助脚本 `aa_to_csv.py` 统一放入 `scripts/`，根目录仅保留必要说明文件。
- 临时/备忘文档：将 `A1111111.md`、`A123GENTS.md`、`BACKUP清单.md` 及日志文件 `backend.log`、`frontend.log` 归档至新建 `misc/` 目录，以免干扰根目录。
- 根目录保留项：`AGENTS.md`、`README.md`、`LICENSE`、`CHANGELOG.md`、`.gitignore`、`backend/`、`frontend/`、`docs/`、`config/`、`scripts/`、`database/`、`misc/`。
- 如有引用路径（README/脚本），后续可按需调整；本次先完成物理归档。

## 实际操作
- 计划移动文件：
  - `.env` → `config/.env`
  - `docker-compose.yml` → `config/docker-compose.yml`
  - `h2-start.sh`、`setup-env.sh`、`simple-start.sh`、`start-project.sh`、`aa_to_csv.py` → `scripts/`
  - `A1111111.md`、`A123GENTS.md`、`BACKUP清单.md`、`backend.log`、`frontend.log` → `misc/`
- 保留根目录其他核心文件与目录不变。
- 实际执行已按上表完成移动；当前根目录仅保留：`AGENTS.md`、`README.md`、`LICENSE`、`CHANGELOG.md`、`.gitignore`、`backend/`、`frontend/`、`docs/`、`config/`、`scripts/`、`database/`、`misc/`。

## 测试与验证
- 本次仅文件归档与路径调整，不涉及代码逻辑；执行后需人工确认 README 或启动脚本引用路径是否需同步更新。***
