# 上传功能实现与当前状态（2025-11-17）

## 核心能力
- 直传（<=10MB）：流式写入+SHA-256 哈希，一次I/O，失败清理物理文件。
- 分片上传（>10MB）：并发3、每片重试3次；断点续传（服务端分片清单 + 本地记录）。
- 合并前补传：在合并前请求核对，自动补传缺失分片。
- 秒传：同用户 + 文件哈希（SHA-256）存在即完成。
- 上传策略：默认 allowAll=false，允许后缀白名单（小写、无点、字母数字）。
- 配额：原子预占，事务失败回滚。
- 清理：分片目录默认保留72小时，定时清理。
- 统一异常：413 超限、400 业务错误、500 兜底。上传相关异常返回统一 JSON。

## 与旧设计差异要点
- 默认策略更安全：allowAll 默认为 false（旧设计默认 true）。
- 存储与哈希：改为流式写入+计算哈希，避免 readAllBytes OOM 与重复I/O。
- 归属校验：folderId 严格校验属于当前用户，防越权。
- 秒传范围：限定“同用户+哈希”，避免跨用户复用引发路径/配额问题。
- 断点续传：服务端提供分片清单与缺失清单；合并前自动补传缺片。
- 分片清理：增加保留期清理任务，避免长期占用。

## 行为与约束
- 白名单校验（allowAll=false 时）：后缀为空/不在白名单/未配置均会拒绝。
- MIME：服务端以文件名推断基础 content-type；如需更严格可后续增加魔数嗅探。
- 失败与回滚：写盘失败会删实体文件；数据库失败回滚配额；合并失败保留分片便于续传。
- 前端限制：默认 100MB 本地预校验；10MB 阈值切换分片；并发3、重试3次可在前端调整。

## 后续可选优化（非当前范围）
- 内容嗅探/病毒查杀：提升内容安全等级。
- 更大文件支持：前端哈希改为增量库，降低内存占用峰值。
- 监控指标：上传耗时、分片失败率、合并成功率指标暴露。
