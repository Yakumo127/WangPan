# UML 活动图绘制与归档标准（企业文件管理系统）

## 目的与范围
- 统一“活动图”（流程/控制流）表达，用于补充时序图，适用于下载、上传审批流、批处理、定时清理等过程。

## 工具与格式
- 使用 PlantUML Activity 语法；文件后缀 `.puml`。
- 中文为主，必要英文关键字（HTTP、路径、类名）。

## 语法约定
- 开始/结束：`start` / `stop`。
- 动作：`:描述;`（单句动词短语）。
- 分支：`if (...) then (是)` / `else (否)` / `endif`；嵌套时缩进对齐。
- 循环或多次尝试：可用 `while (...) is (true)` / `endwhile` 或以注释说明。
- 重要外部约束：在动作后以括注补充（如“要求 ROLE_ADMIN”、“JWT 认证通过”）。

## 分层表达（建议）
- 优先用动作语句描述“做什么”，必要时在括注标出“由谁做/在哪一层做”（如 FileService/Controller/DB/FS）。
- 对数据层/文件系统交互，用“(DB: ...)/(FS: ...)”提示，避免臆造实现细节。

## 归档与命名
- 归档位置：`docs/系统设计/活动图/`。
- 文件命名：中文 + 主题 + “UML活动图” + 时间戳（`YYYYMMDD-HHMMSS`）。
  - 例：`文件下载-UML活动图-20251112-140459.puml`。
- 与时序图分开存放，避免混淆。

## 质量检查
- 覆盖成功/失败/权限分支（如 404/403、不可读）。
- 与实现对齐（接口路径、权限要求、计数更新点）。
- 术语一致（登录、回收站、缩略图等）。

## 示例
- `docs/系统设计/活动图/文件下载-UML活动图-20251112-140459.puml`
