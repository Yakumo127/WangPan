# 文件管理新版移动弹窗多次请求问题分析（2025-11-21 13:23）

## 背景概述
- 用户在“文件管理（新版）”页面中，首次点击“移动”操作时抓包发现 `GET /api/folders/list` 被重复触发约 10 次，经过多轮修复仍未改善，需要重新梳理问题根因与可落地的修复方案。

## 现象与复现
1. 打开新版列表页 `/files-explorer`，页面装载流程会请求一次 `GET /api/folders/list?parentId=null` 以加载当前目录。
2. 点击任意文件/文件夹的“移动”按钮，弹出树形对话框：
   - 打开瞬间再触发 1 次 `GET /api/folders/list?parentId=null`。
   - 若根节点被默认展开或存在多处 `node-key` 激活，Element-Plus Tree 会并发触发多次 `load` 回调，其中每一次都以 `parentId=null` 命中服务端。
   - 若列表中有历史展开过的节点，还会进一步携带 `parentId={某ID}` 打出更多请求。
3. 所有请求在极短时间内返回，后端日志显示都是同一个接口，说明前端并未做去重/缓存。

## 排查过程
- 阅读 `frontend/src/views/files/Explorer.vue`，发现：
  - `loadEntries`（页面装载/刷新）和 `loadFolderTreeRoot`（弹窗初始化）分别独立调用 `getFolderList({ parentId: currentFolderId || null })`，互不共享数据。
  - `folderCache` / `folderLoading` 虽然存在，但 `loadFolderTreeRoot` 每次执行时都会 `folderCache.value = new Map()`，导致根节点缓存永远为空，Tree 再次懒加载时仍会重新请求根列表。
  - 根节点数据没有利用 `folderList` 结果，而是重新向后台发起请求。
  - `loadEntries` 没有防抖，`refreshAll` 内部 `await loadBreadcrumb(); await loadEntries();`，若外部多次调用可能导致 `loadEntries` 并发，再叠加一层重复请求。

## 根因分析
- 缓存重置：弹窗一开就清空 `folderCache`，使得 `loadFolderChildren` 中的缓存逻辑完全失效。
- 数据复用缺失：页面已有的根目录数据没有提供给弹窗树，导致每次都要从后台重取。
- 并发控制缺失：`loadEntries` 允许多次同时请求同一目录列表，未对相同参数进行 Promise 复用或防抖。

## 修复方案
1. **复用根数据**：`loadEntries` 获取的 `folderList` 直接作为移动/复制树的根节点，弹窗打开时仅在本地构造节点，不额外请求。
2. **持久缓存**：
   - `folderCache` 初始化一次并在组件生命周期内持续存在，不再在 `loadFolderTreeRoot` 中重建。
   - 根节点数据写入 `folderCache`（key 使用 `'root'`），Element-Plus Tree 若再次懒加载根节点时直接走缓存。
   - 对 `parentId` 的请求统一通过 `folderLoading` 去重，防止同一个 `parentId` 并发命中。
3. **请求防抖**：为 `loadEntries` / `refreshAll` 引入 keyed promise（例如 `currentFolderId` + 搜索关键字）以避免同时存在多次完全相同的 `GET /api/folders/list`。
4. **辅助优化**：
   - 调整 `expandedKeys`，默认仅选中当前目录而不是展开所有根节点，减少 Tree 自动触发的懒加载次数。
   - 在移动弹窗关闭时保留缓存，不必每次都清空。

## 风险与验证
a. 需要确认移动/复制弹窗在切换目录后仍能显示最新列表。计划在 `refreshAll` 完成后同步刷新 `folderCache` 中的对应 parentId。
b. 需要在修复后通过浏览器 devtools 验证一次移动操作仅触发 1~2 次网络请求（根目录 + 具体展开目录），并在不同目录切换场景重复验证。
