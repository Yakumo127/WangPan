# 备份导出排错与修复记录（2025-11-18）

本文记录“导出只有 db.json、缺少 manifest 与 blobs”的问题排查、根因与修复，以及附带的稳健性增强与验证结论，便于后续复盘与参考。

## 1. 现象

- 在线/服务器导出生成的 zip 包仅包含 `db.json`，没有 `manifest.json` 与 `blobs/`、`thumbnails/` 目录。
- 异步作业（Export Job）初期显示：
  - 失败示例：
    - Job 2/3：`error = 导出失败: IOException: Stream closed`，`stage = export:init`
    - Job 9：`error = UnexpectedRollbackException: Transaction silently rolled back ...`，`stage = export:begin`
  - 成功示例（修复后）：
    - Job 10：`status = SUCCEEDED`，`stage = export:manifest`，`bytes = 66870706`

## 2. 根因

1) Zip 流被过早关闭（两处）
   - 写 `db.json` 时，`JsonGenerator.close()` 默认会关闭底层 `ZipOutputStream`，导致后续条目写入时报 `IOException: Stream closed`。
   - 写 `manifest.json` 时同理。

2) 事务代理遮蔽真实 I/O 异常
   - `BackupService` 类上存在 `@Transactional(readOnly=true)`，导出方法被事务代理包裹。内部异常发生时标记 `rollback-only`，最终提交阶段统一抛 `UnexpectedRollbackException`，掩盖了真正的 I/O 错误。

## 3. 修复

3.1 禁止 JsonGenerator 关闭底层 Zip 流（两处）
- 位置：
  - `backend/src/main/java/com/filemanager/service/BackupService.java: writeDbJson(...)`
  - `backend/src/main/java/com/filemanager/service/BackupService.java: writeManifest(...)`
- 做法：
  - 使用“非关闭包装流”包裹 `ZipOutputStream`（`FilterOutputStream#close` 仅 flush，不关闭底层）。
  - 禁用 `AUTO_CLOSE_TARGET`，确保 `JsonGenerator` 关闭不再关闭底层 Zip 流。

3.2 导出流程禁用事务
- 位置：
  - `BackupService.exportToServerWithProgress(...)`
  - `BackupService.exportToStreamWithProgress(...)`
- 做法：
  - 标注 `@Transactional(propagation = NOT_SUPPORTED)`，导出过程不参与事务，真实 I/O 异常原样抛出。

## 4. 稳健性与可观测性增强

- 作业阶段打点（便于定位）：
  - `export:whitelist → export:realpath → export:openOut → export:openZip → export:db → export:collect → export:copy:<hash前缀> → export:thumb → export:manifest`。
  - 代码：`BackupService` + `BackupJobService`。
- 错误信息增强：
  - 失败时包含异常类型、关键信息与栈（作业详情可见）。
- 文件名避免碰撞：
  - 服务器导出 zip 名称改为 `backup-YYYYMMDD-HHmmss-SSS-<6随机>.zip`。
- 白名单与安全：
  - 增加 realpath 校验，防符号链接逃逸（`BackupService.validateWhitelist/realpath`）。
- 冻结并发计数：
  - `backup.gc.freeze.count`、`backup.admin-purge.freeze.count`，避免并发导出提前解冻。
- 导入全程强维护锁：
  - `system.maintenance.level=all`，导入期间拦截读写（放行备份相关接口），并冻结 GC/管理员清理。
- 内部表保护：
  - JSON 导入 TRUNCATE 阶段排除 `backup_jobs`，避免“自删作业记录”。
- 前端 UI：
  - “作业与进度”列表新增“错误”列与“详情”对话框；异步作业可点击查看 stage/error/params/stats。

## 5. 验证结论

- 成功作业示例：
  - Job 10：`SUCCEEDED`，`stage = export:manifest`，`bytes = 66,870,706`，`path = /work/work_dir/20251118`。
  - 生成的 zip 内含 `manifest.json`、`db.json`（或 `db.sql` 视 mysqldump 可用性）与 `blobs/`（及 `thumbnails/` 选项）。
- 失败时定位：
  - 通过阶段/错误栈可快速定位（如 `export:openOut` → 权限/路径；`export:db` → mysqldump；`export:copy` → 源文件读 I/O）。

## 6. 操作指引（摘）

- 服务器导出（推荐先配置白名单）：
  - 前端：系统设置 → 备份与迁移 → “定时备份与白名单”卡片 → 白名单与目标目录 → “导出到服务器”。
  - 或异步方式：点击“异步导出（创建作业）”，到“作业与进度”查看。
- 下载导出：
  - GET `/api/admin/settings/backup/export?format=sql|json&includeThumbnails=true|false&mode=online|maintenance`。
- 导入（全量替换）：
  - 先“预检”→ 再“导入”（导入期间：全局只读 + 冻结 GC/清理）。

## 7. 变更清单（主要文件）

- `backend/src/main/java/com/filemanager/service/BackupService.java`
  - 新增阶段打点、禁用 AUTO_CLOSE_TARGET、非关闭包装流、NOT_SUPPORTED。
- `backend/src/main/java/com/filemanager/service/ImportService.java`
  - 导入维护锁/冻结；内部表保护；流式复制释放；SQL 预检。
- `backend/src/main/java/com/filemanager/service/BackupJobService.java`
  - 阶段推进与错误栈记录；“export:begin”打点。 
- `backend/src/main/java/com/filemanager/config/MaintenanceReadOnlyConfig.java`
  - 维护级别：`write-only | all`，导入时使用 `all`。
- `backend/src/main/java/com/filemanager/task/BackupScheduler.java`
  - 读取 format/mode/includeThumbnails 配置；保留策略。
- `frontend/src/views/admin/System.vue`
  - 新增“作业详情”对话框与“错误”列；导出/导入交互完善。

## 8. 建议

- 大规模数据建议优先使用 `format=sql`（mysqldump 可用时），速度/体积更优；不可用则回退 JSON（已流式化）。
- 定时备份请配置白名单、目标目录与保留策略；推荐在非高峰期执行。
- 失败时优先查看“作业详情”的阶段与错误栈，可快速定位（权限/路径/空间/白名单/I/O）。
