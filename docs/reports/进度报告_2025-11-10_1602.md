# 企业级文件管理系统 — 详细进度与代码分析报告（2025-11-10 16:02）

## 一、项目概览
- 技术栈：Spring Boot 3、Spring Security、JPA、MySQL、Redis、JWT、Vue 3、Element Plus。
- 架构：前后端分离；后端提供 REST API；前端通过 `/api` 代理访问；支持 Docker Compose 与脚本启动。
- 目标：企业级文件管理（用户/文件/文件夹/回收站/分享/配额/日志/管理员后台）。

## 九、未实现/简化/存在差异（需改进）
1) 分享模块缺失（后端无 Controller/Service，前端 Share.vue 为演示数据）
2) 存储配额未落地（User 实体有配额字段；上传/删除/恢复未校验或更新配额）
3) 操作日志未接入（仅有实体 UserLog；无 AOP/拦截器记录核心操作）
4) 文件夹路径接口为简化实现（仅返回当前节点；未构造完整路径链）
5) 下载放行与控制器鉴权不一致
   - 放行：`/api/files/download/**`（SecurityConfig.java:47）
   - 控制器：依赖登录态获取 userId（FileController.java:75-79）；未登录将失败/报 400
   - 建议：去掉放行，或支持公开访问的下载逻辑（附授权校验）
6) 缩略图公开访问策略（安全考虑）
   - 当前公开可访问（SecurityConfig.java:48）；未做文件授权校验
   - 建议：改为需登录 + 所有权/授权校验，或仅公开分享链接对应资源
7) application.yml 缩进错误（重要）
   - `redis:` 与 `cache:` 被缩进在 `jwt:` 下（backend/src/main/resources/application.yml）
   - 可能导致 Spring Redis/Cache 配置不生效
   - 建议：提升到顶层，与 `spring:`、`server:` 同级
8) Captcha 大小写不一致（Bug）
   - 生成存入大小写不变（CaptchaService.java:25），校验用 `toLowerCase()` 查找键（CaptchaService.java:90）
   - 导致校验失败（通常）
   - 建议：生成与校验统一大小写（都转小写）
9) 大文件哈希计算方式（性能）
   - 使用 `Files.readAllBytes`（FileService.java:362），占用内存大
   - 建议：流式计算 MessageDigest，降低内存峰值
10) 管理员初始化日志（信息暴露）
   - `DataInitializer` 打印管理员密码 Hash（backend/src/main/java/com/filemanager/config/DataInitializer.java）
   - 建议：移除或降级日志级别，避免泄露敏感信息
11) 管理员导入统计 `skipped` 未使用（语义保留）
   - 现逻辑返回“新增/更新/失败”，`skipped` 恒 0
   - 可扩展：重复行/空行/违规行归类为 `skipped`
12) 前端遗留变量（清理）
   - `enableImportExport` 变量残留未使用（frontend/src/views/admin/Users.vue 脚本区）
   - 建议：移除无用变量
13) JWT Secret 长度建议
   - `JwtUtils` 使用 `Keys.hmacShaKeyFor`，推荐 32+ 字节
   - 当前 `enterpriseFileManagerSecretKey2024` 可能偏短，建议加长/读取外部安全配置
