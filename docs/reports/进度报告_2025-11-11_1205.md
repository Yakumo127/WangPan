# 企业级文件管理系统 — 项目进度报告（2025-11-11 12:05）

**项目概览**
- 后端：Spring Boot 3 + JPA + Security + JWT；MySQL + Redis；文件存储于 `file.storage.path`
- 前端：Vue 3 + Element Plus + Axios
- 部署：Docker/Compose 与单容器镜像（`config/`、`docker-compose.yml`）

**本次变更（软删与配额 + 管理员排期删除 + 管理员恢复目标）**
- 软删与配额语义重构
  - 用户删除：立即释放容量，仅一次；恢复时校验容量并回加
  - 用户“回收站彻底删除/清空”：仅对用户隐藏，不物理删除
  - 管理员删除：改为“排期删除”，进入 15 天冷静期，到期由定时任务物理清理
  - 管理员恢复：从系统回收站恢复到当前管理员账号的网盘空间，并扣减管理员配额
- 配置与任务
  - 新增 `recycle.admin.retention-days: 15`、定时清理任务 `recycle.purge.fixed-delay-ms`
- 接口增强
  - 用户删除、用户恢复、管理员恢复接口返回配额，便于前端即时刷新

**接口与行为变化一览**
- 用户侧
  - DELETE `/api/files/{fileId}`：删除 → 释放配额；返回 `quotaUsed/quotaLimit`（backend/src/main/java/com/filemanager/controller/FileController.java:175）
  - PUT `/api/files/{fileId}/restore`：恢复 → 校验并回加配额；返回 `quotaUsed/quotaLimit`（backend/src/main/java/com/filemanager/controller/FileController.java:331）
  - DELETE `/api/files/recycle/bin/{fileId}`：仅对用户隐藏（ownerHidden=true）（backend/src/main/java/com/filemanager/service/FileService.java:304）
  - DELETE `/api/files/recycle/bin/empty`：批量仅隐藏（backend/src/main/java/com/filemanager/service/FileService.java:344）
- 管理员侧
  - GET `/api/files/admin/recycle/bin`：全局回收站（含删除时间与排期状态）（backend/src/main/java/com/filemanager/controller/FileController.java:286）
  - POST `/api/files/admin/recycle/bin/{fileId}/schedule-delete`：提交排期删除，body: `{reason}`；返回执行时间（backend/src/main/java/com/filemanager/controller/FileController.java:308）
  - POST `/api/files/admin/recycle/bin/purge-expired`：手动清理到期项（backend/src/main/java/com/filemanager/controller/FileController.java:382）
  - PUT `/api/files/admin/{fileId}/restore`：恢复到当前管理员网盘；返回管理员配额（backend/src/main/java/com/filemanager/controller/FileController.java:308）

**前端影响与建议**
- 用户端
  - 删除/恢复后用接口返回的 `quotaUsed/quotaLimit` 直接刷新容量展示
  - 回收站“彻底删除/清空”改文案为“仅从你的回收站移除（管理员仍可见）”
- 管理端
  - 全局回收站：展示 deleteTime、adminDelete* 字段；删除动作两次确认，第二次提交 reason 调用 `schedule-delete`
  - 增加“手动清理到期”按钮调用 `purge-expired`；移除“清空所有回收站”

**验证建议**
- 用户：上传→删除（quota 减）→恢复（quota 加/不足报错）→回收站彻底删除（仅隐藏）→清空回收站（仅隐藏）
- 管理员：列表→schedule-delete（返回 executeTime）→restore 到管理员（管理员 quota 加，文件迁移目录）→purge-expired（或等待定时任务）
