# 仪表盘聚合接口与真实数据方案（2025-11-25 10:41）

## 问题成因
- 前端 `Dashboard.vue` 采用硬编码的 `stats/activities`，未调用任何后端接口，导致指标与时间线展示的是假数据。
- 分享统计在前端同样为 mock，后端尚无分享相关接口，口径缺失。
- 现有接口虽能提供文件/文件夹/回收站数据，但需要多次请求与前端自行计算，缺乏统一聚合口径。

## 排查过程与历史
- 检查前端代码：确认 `Dashboard.vue` 的统计卡片与时间线均为常量，唯一真实字段仅存储配额（来自 `authStore.user`）。
- 检查后端接口：已存在 `/api/files/list`、`/api/folders/list`、`/api/files/recycle/bin`、`/api/auth/userinfo` 等可用真实数据源；审计日志 `UserLog` 可用于最近动态；未发现分享相关接口。
- 结论：需在后端提供聚合接口统一计数与动态查询，前端改为单一请求获取真实数据。

## 修复建议
1. 后端新增聚合接口 `/api/dashboard/summary`（登录用户作用域），返回文件/文件夹/回收站数量、配额、最近动态/最近上传，统一字段与口径；如需管理员全局视角，可扩展 `/api/admin/dashboard/summary`。
2. 前端新增 `api/dashboard.js` 并在 `Dashboard.vue` 调用聚合接口，移除硬编码 mock；分享缺口可暂时置为 0 或“未接入”。
3. 最近动态优先使用审计日志（上传/下载/删除/恢复等），若日志缺口可退化为最近上传文件。

## 具体实施计划
1. 后端
   - 新增 DTO：`DashboardSummaryDTO`（文件数、文件夹数、回收站数、配额、最近动态列表等）。
   - 新增 Service：聚合 `FileRepository`、`FolderRepository`、`UserLogRepository` 计数/最近动态查询（限制条数，按时间倒序），配额沿用 `User` 数据。
   - 新增 Controller：`/api/dashboard/summary` 获取当前用户 ID 并返回聚合结果；必要时支持 `limit` 参数与管理员全局入口。
2. 前端
   - 新增 `src/api/dashboard.js` 调用新接口。
   - `Dashboard.vue`：将 `stats/activities` 改为响应式，使用接口数据渲染；处理加载与错误状态；分享卡片暂时标记未接入。
3. 验证
   - 后端：单元/集成测试覆盖计数口径、空数据兜底、动态条数限制。
   - 前端：联调比对仪表盘数值与文件/回收站列表一致性；异常态提示。

## 实际采取的修复操作
- 当前阶段：完成问题分析与实施计划，准备按上述步骤新增聚合接口并改造前端仪表盘。
