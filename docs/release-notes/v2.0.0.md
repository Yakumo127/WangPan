# v2.0.0

发布亮点
- 上传/秒传
  - 新增整文件 SHA-256 校验与“秒传”检查接口：`POST /api/files/exists`（判定同一用户且未删除的同哈希文件是否已存在）。
  - 直传：后端边写盘边计算 SHA-256 并入库 `file_hash`，提高一次 IO 的效率。
  - 分片上传：支持分片接收、服务端分片状态查询与分片合并；合并后强制以 SHA-256 校验与客户端 `fileHash` 一致。
- 下载增强
  - 支持 Range/If-Range/ETag/304，支持 HEAD 探活，按需返回 206/304/200，并统计全量与分片下载量。
  - 管理员可下载任意文件（忽略归属），同样支持条件请求与计数。
- 回收站与配额
  - 用户删除进入个人回收站；“彻底删除”会移入系统回收站并释放配额（不立即物理删）。
  - 管理员支持恢复、排期删除与到期清理（物理删除并兜底释放配额）。
- 上传策略
  - 后台可配置“不限制上传类型”或“允许的后缀白名单”，前端支持本地校验与指引。

后端要点
- 控制器
  - `/api/files/upload`：直传写盘并计算 SHA-256。
  - `/api/files/exists`：秒传检查（同用户+未删除）。
  - `/api/files/chunk`、`/api/files/chunk/status`、`/api/files/merge`：分片上传、状态查询与合并校验。
  - `/api/files/download/{id}`、`/api/files/admin/download/{id}`：下载（Range/ETag/304/HEAD）。
- 服务
  - `FileService.uploadFile(...)`：边写边算哈希；失败兜底删除落地文件；原子扣减配额。
  - `FileService.findByHashIfExists(...)`：按 `userId + fileHash + deleted=false` 判断存在性。
  - `FileService.mergeChunks(...)`：合并后校验 SHA-256 与 `fileHash` 一致；创建记录；清理分片。
  - 回收站/管理员排期删除：规范配额释放与物理删除时机。

前端要点
- 上传流程
  - 计算整文件 SHA-256（Web Crypto）；若 `exists=true` 则前端跳过真实上传（当前版本不在目标文件夹新建记录）。
  - 大文件（>10MB）采用分片并发上传，断点续传结合本地记录与服务端状态。
- 管理端
  - 可配置上传后缀策略；导出审计日志 CSV/XLSX。

注意事项 / 已知限制
- 秒传逻辑仅在前端“跳过上传”，不会基于已存在文件在新目标文件夹创建第二条记录；如需“同哈希多目录复用/引用”，需后端新增去重/引用能力（含引用计数与删除策略）。
- 分片路径按 `userId + fileHash` 组织；并发大规模同哈希上传应避免由多个会话同时写入同一分片目录（建议前端避免同用户同哈希并发）。
- 前端整文件哈希采用一次性读取内存计算，超大文件建议改为增量哈希库。
