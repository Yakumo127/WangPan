# 备份与迁移：修复方案（无停机版）

日期：2025-11-18

## 背景
在“备份与迁移（无停机版）”已实现的基础上，结合代码审查与你的要求（导入阶段可以禁止所有操作），对一致性、安全性与可运维性进行加固。

## 核心策略
- 导入全程强维护锁：导入开始即进入“全局只读（含读）”维护模式，仅放行备份/导入相关接口，其他 API 均阻断；导入完毕后解锁。
- 内部表保护：导入过程显式排除内部运行表（如 backup_jobs）不被 TRUNCATE/覆盖，避免“自删作业记录”。
- 导出流式化与复制释放：JSON 导出使用流式游标；文件复制修复资源释放，避免 OOM/句柄泄漏。
- 后续增强（阶段二）：冻结并发计数/租约、白名单 realpath 校验等。

## 修复项（阶段一）
1) 导入隔离与流程
   - 扩展维护锁级别：`system.maintenance.level=write-only|all`。导入阶段置 `all`，拦截 GET/HEAD/OPTIONS 以外的所有请求；放行仅限 `/api/admin/settings/backup/*` 与 `/api/admin/settings/maintenance`。
   - 导入窗口冻结后台清理：设置 `backup.gc.freeze=true` 与 `backup.admin-purge.freeze=true`；导入结束后恢复。
   - 默认保留异步导入能力，但通过“内部表保护”避免清空作业表。
2) JSON 导出流式化（避免 OOM）
   - 每张表使用流式游标（MySQL：`setFetchSize(Integer.MIN_VALUE)`）逐行写出到 `db.json`，严格关闭连接与结果集。
3) 文件复制资源释放
   - 复制与统计使用 `Files.walk(..)` 的 try-with-res 关闭流，避免句柄泄漏；支持进度/取消。
4) 内部表保护与 SQL 预检
   - JSON 导入 TRUNCATE 阶段排除黑名单：`backup_jobs`（如有新增内部表可扩展）。
   - SQL 导入预检：若检测到 `CREATE DATABASE`、`DROP DATABASE`、`USE 数据库` 等数据库级语句，拒绝执行并提示使用 JSON 或清洗后再导入。

## 后续增强（阶段二，按需）
- 冻结并发计数/租约：`backup.*.freeze` 从布尔改为计数/TTL，仅在计数归零/租约到期时解冻，避免并发导出时提前解冻。
- 服务器路径白名单 realpath 校验：防止符号链接逃逸白名单目录。
- 定时备份读取配置：format/mode/includeThumbnails 读取系统设置。
- 缩略图回退命名去碰撞：`_external/{hash}-{filename}`。
- 下载文件名增强：`filename*=` 兼容 RFC 5987。
- 作业输出最小化：返回 DTO 或忽略 createdBy。

## 验收
- 导入阶段：非备份相关接口返回 423，导入成功后恢复；GC/清理冻结与恢复正常。
- JSON 导出/导入：大表场景稳定，无 OOM；复制无句柄泄漏；作业表未被清空。
