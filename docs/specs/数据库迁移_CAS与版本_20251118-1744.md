# 数据库迁移说明（CAS + 版本）

适用于 MySQL 8。生产环境建议关闭 `ddl-auto` 并使用手工/工具化迁移。

## 1. 新建表与约束
```sql
-- 1) blobs：内容寻址存储
CREATE TABLE IF NOT EXISTS blobs (
  hash            VARCHAR(64)  PRIMARY KEY,
  size            BIGINT       NOT NULL,
  content_type    VARCHAR(255) NULL,
  path            VARCHAR(1024) NOT NULL,
  thumbnail_path  VARCHAR(1024) NULL,
  created_at      DATETIME     NOT NULL,
  last_access_at  DATETIME     NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 2) file_versions：版本记录
CREATE TABLE IF NOT EXISTS file_versions (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  file_id      BIGINT       NOT NULL,
  version_no   INT          NOT NULL,
  blob_hash    VARCHAR(64)  NOT NULL,
  size         BIGINT       NOT NULL,
  content_type VARCHAR(255) NULL,
  comment      VARCHAR(255) NULL,
  created_by   BIGINT       NOT NULL,
  create_time  DATETIME     NOT NULL,
  CONSTRAINT uk_file_version_no UNIQUE (file_id, version_no),
  CONSTRAINT fk_version_file FOREIGN KEY (file_id) REFERENCES files(id)  ON DELETE CASCADE,
  CONSTRAINT fk_version_blob FOREIGN KEY (blob_hash) REFERENCES blobs(hash) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 3) files：增加 active_version_id 外键（如不存在）
ALTER TABLE files ADD COLUMN IF NOT EXISTS active_version_id BIGINT NULL;
ALTER TABLE files ADD CONSTRAINT fk_file_active_version FOREIGN KEY (active_version_id) REFERENCES file_versions(id);
```

## 2. 旧数据迁移（去重 + 建版本）
```sql
-- 以 files.file_hash 分组，选择任意一条物理文件作为源，迁移到 blobs.path（建议由应用层原子移动后执行 INSERT）。
-- 1) 先插入 blobs（应用移动成功后）：
INSERT IGNORE INTO blobs(hash, size, content_type, path, created_at, last_access_at)
SELECT f.file_hash, f.size, f.content_type, f.file_path, NOW(), NOW()
FROM files f
WHERE f.deleted = 0 AND f.file_hash IS NOT NULL AND f.file_hash <> '';

-- 2) 为每条 files 生成 v1 版本（若不存在）：
INSERT INTO file_versions(file_id, version_no, blob_hash, size, content_type, comment, created_by, create_time)
SELECT f.id, 1, f.file_hash, f.size, f.content_type, 'migrated v1', f.user_id, NOW()
FROM files f
LEFT JOIN file_versions v ON v.file_id = f.id AND v.version_no = 1
WHERE f.deleted = 0 AND v.id IS NULL;

-- 3) 回填 active_version_id：
UPDATE files f
JOIN file_versions v ON v.file_id = f.id AND v.version_no = 1
SET f.active_version_id = v.id
WHERE f.active_version_id IS NULL;
```

> 注意：物理移动必须由应用原子执行，避免竞态；SQL 只负责元数据落库/回填。不同 hash 但同内容的历史脏数据不在本 SQL 范围内。

## 3. 清理未引用的 Blob
```sql
-- 仅查询参考：
SELECT b.hash FROM blobs b LEFT JOIN file_versions v ON v.blob_hash = b.hash WHERE v.blob_hash IS NULL;
```

## 4. 回滚策略
- 新表回滚：`DROP TABLE file_versions; DROP TABLE blobs;` 并从 `files` 删除 `active_version_id`。
- 版本字段回滚：将 `files.file_path/hash/size/content_type` 作为真实来源后恢复旧下载逻辑。
