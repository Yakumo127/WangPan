# 文件与文件夹统一管理界面设计方案（2025-11-20 18:31）

## 一、背景与目标

1. 当前状态
- 现有系统中文件与文件夹管理是分开的：
  - 文件列表：`/files` 使用 `List.vue`，只展示文件；
  - 文件夹列表：`/folders` 使用 `folders/List.vue`，只展示文件夹；
  - 文件可以通过上传时选择 `folderId` 放入某个文件夹，但用户视角下没有一个统一的“目录 + 文件”视图。
- 这与现实中的文件管理体验（如操作系统资源管理器、网盘目录视图）存在差距：
  - 用户期望在一个页面中同时看到当前目录下的“文件夹 + 文件”；
  - 通过点击文件夹进入子目录，文件与文件夹在同一个上下文中操作。

2. 本次目标

- 在不破坏现有功能（尤其是已有 `/files`、预览页等）的前提下：
  1. 新增一个“文件与文件夹统一管理”的页面，实现类似资源管理器的视图；
  2. 同时展示当前目录下的文件夹与文件；
  3. 支持在该页面中创建文件夹、上传文件、进入子目录、返回上级目录；
  4. 文件可以放入文件夹中，操作方式与现有接口保持兼容。
- 采用“新增界面 + 新路由”的方式进行试验：
  - 不修改旧页面 `/files` 和旧逻辑；
  - 通过新的菜单项进入“文件管理（新版）”，效果满意后再考虑替换旧界面。

## 二、总体设计概览

1. 新路由与页面

- 新增路由：
  - `path: '/files-explorer'`
  - `name: 'FilesExplorer'`
  - `component: '@/views/files/Explorer.vue'`（新建组件）
  - `meta: { title: '文件管理（新版）', requiresAuth: true }`
- 在 `layout/index.vue` 中新增菜单项：
  - 文案：`文件管理（新版）`
  - index：`/files-explorer`
  - 图标：沿用 `Files` 图标，保证风格一致。

2. 界面布局

- 顶部工具栏：
  - 左侧：
    - “新建文件夹”按钮；
    - “上传文件”按钮（可复用现有上传逻辑）；
  - 右侧：
    - 搜索输入框（可复用现有搜索逻辑，后续考虑是否按目录范围搜索）。
- 面包屑导航：
  - 显示当前路径，如：“根目录 / 部门A / 项目X”；
  - 支持点击面包屑跳转到上级目录。
- 主体列表区域：
  - 单一表格，行中既有“文件夹”行，也有“文件”行；
  - 列：
    - 名称（带图标，文件夹/文件不同图标）；
    - 大小（文件显示大小，文件夹显示空或“—”）；
    - 类型（文件夹/文件类型）；
    - 创建时间；
    - 操作（下载、预览、重命名、删除等）。

3. 与现有功能的关系

- 不修改：
  - `/files` 路由和 `List.vue`；
  - 预览路由 `/preview/:id`、`/file-view/:id` 和对应页面；
  - 现有文件夹管理页面 `/folders`；
  - 后端接口 URL 与语义。
- 新页面仅使用现有接口组合出统一视图：
  - 文件列表：`GET /files/list?folderId=...`；
  - 文件夹列表：`GET /folders/list?parentId=...`；
  - 文件/文件夹操作：复用已有的创建、重命名、删除、移动接口。

## 三、后端接口复用策略

1. 已有接口

- 文件列表：
  - `GET /api/files/list?folderId={folderId}` → `List<File>`
  - 当 `folderId` 为空：返回用户根目录下的文件；
  - 当 `folderId` 指定：返回该目录下的文件。
- 文件夹列表：
  - `GET /api/folders/list?parentId={parentId}` → `List<Folder>`
  - 当 `parentId` 为空：返回用户根目录下的文件夹；
  - 当 `parentId` 指定：返回该目录下的子文件夹。
- 文件操作：
  - 重命名：`PUT /api/files/{id}/rename`；
  - 删除：`DELETE /api/files/{id}`；
  - 移动：`POST /api/files/{id}/move`；
  - 下载：`GET /api/files/{id}/download-url`（直链）。
- 文件夹操作：
  - 创建：`POST /api/folders/create`；
  - 删除：`DELETE /api/folders/{id}`；
  - 重命名：`PUT /api/folders/{id}/rename`；
  - 移动：`POST /api/folders/{id}/move`；
  - 获取路径：`GET /api/folders/{id}/path` → `List<Folder>`（自根到当前）。

2. 统一视图逻辑

- 统一视图所需数据：
  - 当前目录下的“文件夹 + 文件”列表；
  - 当前目录的路径（用于面包屑）。
- 数据源策略：
  - 当前目录 ID：`currentFolderId`（前端状态）；
    - null 表示根目录；
  - 子文件夹列表：`GET /folders/list?parentId=currentFolderId`；
  - 文件列表：`GET /files/list?folderId=currentFolderId`；
  - 目录路径：
    - 当前为根目录：直接使用“根目录”；
    - 非根目录：调用 `GET /folders/{currentFolderId}/path`，获得 `List<Folder>` 作为面包屑。
- 无需新增后端接口，将在前端组合使用现有接口实现统一视图。

## 四、前端实现细节（Explorer.vue）

1. 状态设计

- `currentFolderId: ref(null | number)`：当前所在目录 ID；
- `folderList: ref([])`：当前目录下的文件夹列表；
- `fileList: ref([])`：当前目录下的文件列表；
- `breadcrumbFolders: ref([])`：当前路径的目录数组（根到当前），来自 `getFolderPath` 接口；
- `loading: ref(false)`：列表加载状态；
- `newFolderDialogVisible: ref(false)` + `newFolderName: ref('')`：新建文件夹对话框；
- 复用现有上传相关状态（可简化为“上传到当前目录”）。

2. 数据加载流程

```js
const loadEntries = async () => {
  loading.value = true
  try {
    const [folders, files] = await Promise.all([
      getFolderList({ parentId: currentFolderId.value || null }),
      getFileList({ folderId: currentFolderId.value || null })
    ])
    folderList.value = folders || []
    fileList.value = files || []
  } finally {
    loading.value = false
  }
}
```

3. 面包屑加载

- 根目录：
  - `currentFolderId === null` → 面包屑为 `[ { id: null, name: '根目录' } ]`；
- 非根目录：
  - 调用 `getFolderPath(currentFolderId)`：
    ```js
    const loadBreadcrumb = async () => {
      if (!currentFolderId.value) {
        breadcrumbFolders.value = [{ id: null, name: '根目录' }]
        return
      }
      const path = await getFolderPath(currentFolderId.value)
      // 后端返回自根到当前的 Folder 列表
      breadcrumbFolders.value = [
        { id: null, name: '根目录' },
        ...path.map(f => ({ id: f.id, name: f.name }))
      ]
    }
    ```
- 点击面包屑：
  - 设置 `currentFolderId` 为对应目录 ID（root 为 null）；
  - 调用 `loadBreadcrumb` 和 `loadEntries`。

4. 列表渲染

- 合并视图（文件夹在前，文件在后）：

```js
const entries = computed(() => {
  const folders = (folderList.value || []).map(f => ({
    id: f.id,
    name: f.name,
    type: 'folder',
    createTime: f.createTime,
    size: null,
    raw: f
  }))
  const files = (fileList.value || []).map(f => ({
    id: f.id,
    name: f.originalFilename || f.name || f.filename,
    type: 'file',
    createTime: f.createTime,
    size: f.size,
    contentType: f.contentType,
    raw: f
  }))
  return [...folders, ...files]
})
```

- 表格列：
  - 名称：显示图标 + 名称，文件夹点击进入，文件点击可预览或选中；
  - 大小：文件显示格式化大小，文件夹显示 `--`；
  - 类型：文件夹显示“文件夹”，文件根据 `contentType`/扩展名显示文本；
  - 创建时间：统一展示；
  - 操作：
    - 对文件夹：重命名、删除；
    - 对文件：下载、预览（使用现有预览机制）、重命名、删除。

5. 操作实现（复用现有接口）

- 新建文件夹：

```js
const createFolderInCurrent = async () => {
  // newFolderName 输入验证后
  await createFolder({ name: newFolderName.value, parentId: currentFolderId.value })
  await loadEntries()
}
```

- 进入文件夹：

```js
const enterFolder = (folder) => {
  currentFolderId.value = folder.id
  loadBreadcrumb()
  loadEntries()
}
```

- 返回上级（可通过面包屑实现，无需单独按钮）。

- 文件预览：
  - 可直接复用现有逻辑：
    - 图片 → 使用图片预览对话框；
    - 其他 → 使用旧预览路由 `/preview/:id` 或新预览 `/file-view/:id` 中的一种。

- 文件/文件夹重命名、删除、移动：
  - 直接调用现有接口 `renameFile/deleteFile/moveFile` 和 `renameFolder/deleteFolder/moveFolder`；
  - 操作完成后调用 `loadEntries()` 刷新列表。

## 五、与现有功能的边界

1. 保持旧页面不变

- `/files` 路由和 `List.vue` 不做任何修改；
- `/folders` 路由和 `folders/List.vue` 不做任何修改；
- `/preview/:id` 与 `/file-view/:id` 两种预览页逻辑不变。

2. 仅增加新界面和新入口

- 新增路由 `/files-explorer`；
- 新增菜单项“文件管理（新版）”，指向新的路由；
- 使用现有后端接口组合出统一视图。

3. 数据模型兼容

- 新界面仅读取现有实体 JSON（`File` 与 `Folder`），不修改实体字段（除前面已实现的 `folderPath` 计算属性）；
- 不更改任何接口语义，只新增对现有接口的调用。
