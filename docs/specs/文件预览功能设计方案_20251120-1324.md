# 文件预览功能设计方案（2025-11-20 13:24）

本文设计在现有系统中新增“文件预览”功能，支持按文件类型在浏览器中直接预览内容，同时通过系统设置动态维护“可预览的文件类型”列表，并为后续引入 doc/ppt → PDF 转换预览方案预留扩展点。

## 一、目标与范围

1. 为用户提供文件预览能力：
   - 对支持预览的文件，单击文件名即进入“预览”而不是直接下载；
   - 预览类型覆盖：`doc, ppt, pdf, txt, mp4, jpg, png`（实现时会适当扩展 docx/pptx/jpeg 等变体）。
2. 在“系统设置”中新增“预览配置”区域：
   - 管理员可以通过 UI 配置“允许预览的文件后缀列表”；
   - 默认值为：`doc,ppt,pdf,txt,mp4,jpg,png`（小写、不含点）。
3. 权限与审计：
   - 预览权限与下载业务规则保持一致（谁有权访问文件，谁可以预览），但在代码与审计上作为独立行为，不直接绑定下载接口；
   - 对预览行为记录审计日志，包括成功与失败两种情况。
4. 不做的内容（本轮搁置）：
   - 不引入 doc/ppt → PDF 的实际转换服务，仅提供“尝试预览”能力，真正的转换方案另见“暂时搁置修复事项”；
   - 不对预览做大小限制（即所有允许预览的类型，只要权限通过即可预览）。

## 二、系统设置与配置设计

### 2.1 SystemConfig 配置项

在 `system_config` 表中新增一条配置项：

- `config_key`: `file.preview.allowed.suffixes`
- `config_value`: 逗号分隔的小写后缀列表（不含点），如：
  - `doc,docx,ppt,pptx,pdf,txt,mp4,jpg,jpeg,png`
- `config_type`: `STRING`
- `description`: `允许预览的文件后缀列表（小写、不含点，逗号分隔）`
- `is_system`: `true`
- `is_active`: `true`

### 2.2 SystemSettingService 扩展

位置：`backend/src/main/java/com/filemanager/service/SystemSettingService.java`

1. 新增常量：
   - `KEY_PREVIEW_ALLOWED_SUFFIXES = "file.preview.allowed.suffixes";`

2. 新增读取方法：
   - `public java.util.List<String> getPreviewAllowedSuffixes()`
     - 从 `system_config` 读取 `KEY_PREVIEW_ALLOWED_SUFFIXES`；
     - 若不存在或为空，使用默认值：
       - 默认值建议：`doc,docx,ppt,pptx,pdf,txt,mp4,jpg,jpeg,png`；
     - 将字符串按逗号拆分，去空格、转小写、过滤空项后返回 `List<String>`。

3. 新增写入方法：
   - `public void setPreviewAllowedSuffixes(java.util.List<String> suffixes, com.filemanager.entity.User updatedBy)`
     - 将传入后缀列表统一转小写、去重，校验仅包含 `[a-z0-9]`（必要时可放宽到 `_`）；
     - 至少保留一个合法后缀；
     - 使用 `setString(KEY_PREVIEW_ALLOWED_SUFFIXES, joined, "允许预览的文件后缀列表", updatedBy)` 持久化；
     - 打审计日志，actionType 可沿用 `ACTION_UPDATE_SETTING`。

4. 默认值初始化策略：
   - 若系统初次调用 `getPreviewAllowedSuffixes` 时发现配置不存在：
     - 使用默认值 `doc,docx,ppt,pptx,pdf,txt,mp4,jpg,jpeg,png`；
     - 同时写入 `system_config` 记录，方便在 UI 中直接编辑。

## 三、后端接口设计

### 3.1 管理端预览配置接口

用于系统设置页面维护“可预览后缀列表”。

1. 获取配置：
   - 方法：`GET /api/admin/settings/preview-config`
   - 鉴权：`ROLE_ADMIN`
   - 返回示例：
     ```json
     {
       "allowedSuffixes": ["doc", "docx", "ppt", "pptx", "pdf", "txt", "mp4", "jpg", "jpeg", "png"]
     }
     ```
   - 实现：调用 `systemSettingService.getPreviewAllowedSuffixes()`。

2. 更新配置：
   - 方法：`PUT /api/admin/settings/preview-config`
   - 鉴权：`ROLE_ADMIN`
   - 请求体示例：
     ```json
     {
       "allowedSuffixes": ["pdf", "txt", "jpg", "png", "mp4"]
     }
     ```
   - 校验规则：
     - 所有后缀统一转小写；
     - 不允许包含点、空格和特殊字符，仅 `[a-z0-9]`；
     - 至少保留 1 个后缀；
   - 实现：调用 `systemSettingService.setPreviewAllowedSuffixes(...)`；
   - 失败返回 400 + 错误提示（如“存在非法后缀：xx”）。

### 3.2 文件预览权限与元信息接口

#### 3.2.1 预览权限规则

预览权限与下载权限“业务规则保持一致”，但代码层面独立：

- 普通用户：
  - 必须是文件所有者；
  - 调用类似 `fileService.getFileForPreview(fileId, userId)`（内部实现可复用 `getFileForDownload` 的逻辑，但 action 类型与审计区分开）。
- 管理员：
  - 通过专用方法（如 `getFileByIdForAdmin(fileId)`）获取任意文件用于预览。

后续如需实现“可预览但不可下载”的更细粒度控制，可以在 `getFileForPreview` 中叠加额外策略，而不影响现有下载逻辑。

#### 3.2.2 预览元信息接口（可选）

接口：`GET /api/files/{fileId}/preview/meta`

用途：前端在决定单击行为时可以获取服务器对“是否允许预览”的判定。首版可以暂不强依赖该接口，直接由前端根据扩展名与配置判断显示行为，本接口保留作为扩展。

- 鉴权：必须已登录。普通用户只能查自己文件，管理员可查任意。
- 返回示例：
  ```json
  {
    "previewable": true,
    "reason": null,
    "type": "image|video|document|text|unknown",
    "suggestedViewer": "image|video|pdf|text|office"
  }
  ```

实现要点：

1. 获取当前用户及文件实体（预览权限规则同上）。
2. 根据 `originalFilename` 或 `contentType` 解析扩展名，转小写（不含点）。
3. 判断扩展名是否在 `getPreviewAllowedSuffixes()` 中：
   - 在 → `previewable = true`；
   - 不在 → `previewable = false`，`reason = "该类型未在预览列表中"`。
4. 根据扩展名映射 `type` 与 `suggestedViewer`：
   - `jpg/jpeg/png` → `type=image`，`viewer=image`；
   - `mp4` → `type=video`，`viewer=video`；
   - `pdf` → `type=document`，`viewer=pdf`；
   - `txt` → `type=text`，`viewer=text`；
   - `doc/docx/ppt/pptx` → `type=document`，`viewer=office`。

### 3.3 实际预览接口

核心接口：`GET /api/files/{fileId}/preview`

目标：

- 针对支持预览的类型返回浏览器可直接渲染的内容；
- 使用 `Content-Disposition: inline`，不强制下载；
- 复用现有的流式读取与 Range/ETag 支持。

实现思路：

1. 权限与存在性校验：
   - 普通用户：`fileService.getFileForPreview(fileId, currentUserId)`；
   - 管理员：`fileService.getFileByIdForAdmin(fileId)`。
2. 扩展名与类型判断（同 preview/meta）：
   - 若扩展名不在允许列表中，返回 400 或 403，并记录“预览失败”日志。
3. 设置 Content-Type 与 Content-Disposition：
   - 图片（jpg/jpeg/png）：
     - `Content-Type: image/jpeg` / `image/png`；
     - `Content-Disposition: inline; filename="xxx"`。
   - 视频（mp4）：
     - `Content-Type: video/mp4`；
     - 支持 Range，允许浏览器拖动进度条；
   - 文本（txt）：
     - `Content-Type: text/plain; charset=utf-8`；
   - PDF：
     - `Content-Type: application/pdf`；
   - Office 文档（doc/docx/ppt/pptx）：
     - 首版：`Content-Type` 设置为标准 Office 类型（如 `application/msword`、`application/vnd.ms-powerpoint` 等），`Content-Disposition: inline`；
     - 浏览器若支持预览则内嵌展示，否则可能弹“用本地程序打开”或下载（视为“预览尝试”，由前端提示解释）。
4. 流式返回：
   - 可以复用 `buildDownloadResponse` 的大部分逻辑，将其中 `Content-Disposition` 改为 `inline`；  
   - 或抽取公共流式方法，分别用于下载与预览。

### 3.4 审计与日志

预览行为需要单独审计，区分于下载：

1. 新增审计 action 类型：
   - 在 `UserLog` / `com.filemanager.entity.UserLog` 中新增常量：
     - `ACTION_PREVIEW = "PREVIEW"`；
     - `ACTION_PREVIEW_FAIL = "PREVIEW_FAIL"`（可选，也可以只有 PREVIEW + status=FAIL）。
2. 记录成功预览：
   - 在预览接口成功返回时记录：
     - 用户 ID、文件 ID、文件名、预览类型（image/video/pdf/text/office）、耗时等；
3. 记录失败预览：
   - 对于权限不足、类型不支持、文件不存在等情况：
     - 记录失败行为，包含错误原因（例如“预览类型不允许”、“文件不存在”、“无权限”等）。

可按现有下载审计实现方式，复用 `AuditLogService` 的结构。

## 四、前端设计

### 4.1 触发方式与交互规则

1. **单击文件名 = 预览**：
   - 对于“可预览类型”的文件（扩展名在配置列表内）：
     - 单击文件名触发预览（不触发下载）；
   - 对于不可预览类型：
     - 单击文件名可以保留为“无动作”或提示“暂不支持预览”，下载仍通过独立“下载”按钮。

2. **预览形态**：
   - 图片（jpg/jpeg/png）：
     - 在当前列表页弹出大号 `el-dialog` 进行预览：
       - 支持关闭、适当的缩放/居中展示；
   - 其他类型（pdf/txt/mp4/doc/ppt 等）：
     - 跳转到独立预览路由页面（例如 `/preview/:id`），由该页面选择合适的展示方式：
       - PDF：`<iframe :src="previewUrl">`；
       - TXT：用 fetch + `<pre>` 展示文本，或 `<iframe>`；
       - MP4：`<video controls :src="previewUrl"></video>`；
       - Office（doc/ppt...）：使用 `<iframe :src="previewUrl">`，并在顶部说明“预览能力取决于浏览器支持”。

3. 下载与预览分离：
   - “下载”保持独立按钮（不在文件名上直接触发），走现有下载直链机制；
   - 用户预期清晰：点击文件名 = 尝试在页面预览；点击“下载”按钮 = 下载文件。

### 4.2 系统设置中的“预览配置”区域

文件：`frontend/src/views/admin/System.vue`

1. 新增一个 Tab：
   - 与“基础设置 / 系统信息 / 备份与迁移”等同级，如命名为“预览配置”；
2. 预览配置表单内容：
   - `el-select` 多选框 + `allow-create`：
     - 允许管理员输入后缀（小写，不含点），按回车新增；
   - 校验逻辑：
     - 仅允许小写字母和数字，不含点、空格；
     - 至少 1 个后缀；
   - “恢复默认”按钮：
     - 一键恢复为默认列表：`doc,docx,ppt,pptx,pdf,txt,mp4,jpg,jpeg,png`；
   - “保存”按钮：
     - 调用 `PUT /api/admin/settings/preview-config`；
     - 成功提示“预览配置已保存”。

3. 前端缓存：
   - 系统设置页面加载时调用 `GET /api/admin/settings/preview-config` 作为初始值；
   - 文件列表/Home/Admin Files 页面可按需从后端拉取一次预览后缀配置或复用全局缓存，提高体验。

### 4.3 预览页与图片预览对话框

1. 图片预览对话框：
   - 在文件列表页（及需要的页面）中引入一个全局 `previewImageUrl` 与 `previewDialogVisible`；
   - 单击图片类文件名时，直接设置 `previewImageUrl = /api/files/{id}/preview` 并打开对话框。

2. 独立预览页：
   - 新增路由：`/preview/:id`；
   - 该页面在 `onMounted` 时根据文件 ID 调用元信息接口或解析扩展名，决定使用何种组件展示；
   - 提供“返回文件列表”按钮。

## 五、doc/ppt → PDF 转换预览方案（搁置项）

对于 Office 文档（doc/docx/ppt/pptx），理想的预览体验是：在后端将文档转换为 PDF，再以 PDF 形式在浏览器中稳定预览。本轮实现中暂不引入转换服务，仅通过浏览器自身能力尝试预览。

后续计划（作为“暂时搁置修复事项”记录）：

1. 评估并选择文档转换方案：
   - 本地部署 LibreOffice headless + JODConverter；
   - 或接入外部文档预览服务（如 OnlyOffice/Office Online 等）。
2. 设计 doc/ppt → PDF 的缓存与失效策略：
   - 首次预览时转换并落盘；后续预览命中缓存；
   - 原文件更新后，自动失效旧 PDF。
3. 在预览接口中：
   - 对 doc/ppt 文件先转换为 PDF，再以 PDF 形式返回给前端；
   - 统一使用 PDF 预览组件展示。

上述内容已在 `docs/暂时搁置修复事项.md` 中以“doc/ppt 转 PDF 预览方案”形式登记，便于后续单独排期实现。

## 六、总结

本方案在不引入复杂转换服务的前提下，先为浏览器原生支持的类型（pdf/txt/image/mp4 等）提供稳定预览能力，并对 doc/ppt 等 Office 文档提供“尝试预览”的入口。通过系统设置中的“预览配置”，管理员可以灵活控制可预览类型，而预览行为在权限、安全和审计层面都与下载逻辑隔离，便于后续迭代与加固。
