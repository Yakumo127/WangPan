# 存储与垃圾分片清理页面与 API 设计（2025-11-20 20:25）

## 一、目标与范围

### 1.1 功能目标

在系统设置中新增一个“存储与空间”页面（Tab），仅对管理员开放，用于：

1. 展示当前项目所有文件在硬盘上的总占用空间；
2. 展示系统中“垃圾分片”的占用空间；
3. 按用户归纳垃圾分片数量与大小，支持按用户查看与按用户清理；
4. 提供全局“手动清理垃圾分片”能力，释放磁盘空间。

### 1.2 垃圾分片定义

本设计中，“垃圾分片”定义为：

- 存放在 `{storagePath}/chunks/user_{uid}/{fileHash}/chunk_x.part` 下的分片文件；
- 对应的 `userId + fileHash` 在 **最近 1 小时内没有新的分片写入**；
- 且不存在被视为“活跃上传任务”的状态（当前阶段可简化为：仅凭时间窗口判断，无额外任务表）。

清理行为：

- 仅删除满足上述条件的分片文件，不影响正常上传/合并中的分片；
- 实现为“手动触发”的清理操作，默认不会自动周期清理（周期清理可以在后续运维脚本或独立任务中实现）。

## 二、后端设计

### 2.1 概览统计接口

#### 2.1.1 接口定义

- URL：`GET /api/admin/storage/summary`
- 权限：管理员（例如 `ROLE_ADMIN`）
- 功能：返回当前系统文件总占用空间、垃圾分片总占用空间，以及按用户归纳的垃圾分片统计。

#### 2.1.2 响应结构（示例）

```json
{
  "totalUsedBytes": 1234567890,
  "garbageChunksBytes": 12345678,
  "perUserGarbage": [
    {
      "userId": 1,
      "username": "admin",
      "displayName": "系统管理员",
      "chunkCount": 12,
      "chunkBytes": 3456789,
      "oldestChunkTime": "2025-11-20T08:00:00Z",
      "newestChunkTime": "2025-11-20T09:30:00Z"
    },
    {
      "userId": 2,
      "username": "alice",
      "displayName": "Alice",
      "chunkCount": 5,
      "chunkBytes": 1234567,
      "oldestChunkTime": "2025-11-20T07:50:00Z",
      "newestChunkTime": "2025-11-20T09:10:00Z"
    }
  ]
}
```

说明：

- `totalUsedBytes`：整个系统实际文件与 Blob 在存储上的总占用空间（不含分片目录或可选是否包含，建议包含正式文件与 Blob，分片另算）；  
- `garbageChunksBytes`：当前被判定为垃圾分片的总大小；  
- `perUserGarbage`：对垃圾分片按用户归纳的统计结果。

#### 2.1.3 实现要点

- `totalUsedBytes`：
  - 通过遍历 `storagePath` 下正式文件目录与 Blob 存储目录累加得到；  
  - 为避免每次计算开销过大，可考虑：
    - 将该统计结果缓存 1 分钟左右；  
    - 或在上传/删除时维护一个近似的统计值，在“存储与空间”页只做轻量校验。

- `garbageChunksBytes` 与 `perUserGarbage`：
  - 遍历 `storagePath/chunks` 目录：
    - 每个用户子目录：`user_{uid}`；
    - 对每个 `fileHash` 子目录：
      - 检查其分片文件 `chunk_x.part` 的最近修改时间；
      - 若最近修改时间距当前时间超过 1 小时，则判定为“候选垃圾”；
      - 将该目录下所有分片大小累加为 `chunkBytes`；
      - `oldestChunkTime` / `newestChunkTime` 取该目录中分片时间的最小/最大值。
  - 时间判断建议使用 `Instant.now()` 与 `Files.getLastModifiedTime` 对比。

### 2.2 清理接口

#### 2.2.1 全局清理接口

- URL：`POST /api/admin/storage/cleanup/garbage-chunks`
- 权限：`ROLE_ADMIN`
- 功能：清理所有符合垃圾分片条件的分片文件。

请求体（可选）：

```json
{
  "dryRun": false
}
```

- `dryRun = true` 时只计算将要清理的数量与大小，不实际删除，可作为后续增强；
- 当前阶段可忽略 `dryRun` 或默认 false。

响应示例：

```json
{
  "deletedChunks": 123,
  "deletedBytes": 4567890
}
```

#### 2.2.2 按用户清理接口

- URL：`POST /api/admin/storage/cleanup/garbage-chunks/by-user`
- 权限：`ROLE_ADMIN`
- 请求体：

```json
{
  "userId": 2
}
```

功能：

- 仅清理指定 `userId` 的垃圾分片。

响应与全局类似：

```json
{
  "deletedChunks": 12,
  "deletedBytes": 345678
}
```

#### 2.2.3 实现要点与安全性

- 权限严格控制：
  - 两个清理接口必须使用管理员权限注解（如 `@PreAuthorize("hasAuthority('ROLE_ADMIN')")`），防止非管理员调用。

- 清理逻辑与统计逻辑复用：
  - 清理时可复用统计逻辑对 `chunks/user_{uid}` 目录做一遍扫描：
    - 全局清理时：对所有用户进行扫描；
    - 按用户清理时：仅扫描指定 `userId` 目录。

- 审计：
  - 建议在清理接口上增加审计注解（若系统已有审计机制），记录管理员操作。

## 三、前端页面设计（系统设置 → 存储与空间）

文件位置：`frontend/src/views/admin/System.vue` 中新增 Tab。

### 3.1 Tab 与布局

- 在系统设置 `el-tabs` 中新增 Tab：

```vue
<el-tab-pane label="存储与空间" name="storage">
  <!-- 存储与垃圾分片清理内容 -->
</el-tab-pane>
```

- 页面结构：
  1. 顶部卡片：展示总占用 & 垃圾分片总占用 + 全局清理按钮；
  2. 下方表格：按用户展示垃圾分片统计与按用户清理按钮。

### 3.2 顶部概览卡片

示例布局：

```vue
<el-card class="box-card">
  <template #header>
    <div class="card-header">
      <span>存储概览</span>
    </div>
  </template>
  <div class="storage-summary">
    <div class="summary-item">
      <div class="label">总文件占用</div>
      <div class="value">{{ formatFileSize(summary.totalUsedBytes) }}</div>
    </div>
    <div class="summary-item">
      <div class="label">垃圾分片占用</div>
      <div class="value">{{ formatFileSize(summary.garbageChunksBytes) }}</div>
    </div>
    <div class="summary-actions">
      <el-button
        type="danger"
        :loading="cleaningAll"
        @click="confirmCleanupAll"
      >
        清理所有垃圾分片
      </el-button>
    </div>
  </div>
</el-card>
```

交互：

- 点击“清理所有垃圾分片”时，弹出 `ElMessageBox.confirm`：

```js
const confirmCleanupAll = async () => {
  try {
    await ElMessageBox.confirm(
      `将清理所有“超过 1 小时未合并且无活跃上传任务”的分片文件，本操作不可恢复。` +
      `\n预计可释放约 ${formatFileSize(summary.value.garbageChunksBytes || 0)} 磁盘空间，是否继续？`,
      '确认清理',
      { type: 'warning', confirmButtonText: '继续', cancelButtonText: '取消' }
    )
    cleaningAll.value = true
    const res = await cleanupGarbageChunks() // 调用全局清理接口
    ElMessage.success(`已清理 ${res.deletedChunks || 0} 个分片，释放 ${formatFileSize(res.deletedBytes || 0)} 空间`)
    await reloadStorageSummary()
  } catch (e) {
    if (e !== 'cancel') ElMessage.error(e?.message || '清理失败')
  } finally {
    cleaningAll.value = false
  }
}
```

```js
const confirmCleanupUser = async (row) => {
  try {
    await ElMessageBox.confirm(
      `将清理用户「${row.displayName || row.username}」所有“超过 1 小时未合并且无活跃上传任务”的分片文件，本操作不可恢复。` +

```

### 3.4 与现有 System.vue 的集成

1. 在 `setup` 中增加状态：

- `const storageSummary = ref({ totalUsedBytes: 0, garbageChunksBytes: 0, perUserGarbage: [] })`
- `const loadingStorage = ref(false)`
- `const cleaningAll = ref(false)`

2. 新增 API 封装文件（建议）：`frontend/src/api/storage.js`：

```js
import request from '@/utils/request'

export function getStorageSummary() {
  return request({
    url: '/admin/storage/summary',
    method: 'get'
  })
}

export function cleanupGarbageChunks() {
  return request({
    url: '/admin/storage/cleanup/garbage-chunks',
    method: 'post'
  })
}

export function cleanupGarbageChunksByUser(body) {
  return request({
    url: '/admin/storage/cleanup/garbage-chunks/by-user',
    method: 'post',
    data: body
  })
}
```

3. 在 System.vue 中按 `activeTab === 'storage'` 时加载 `storageSummary`。

## 四、权限与安全总结

1. 所有 `/api/admin/storage/...` 接口仅对 `ROLE_ADMIN` 开放；
2. 清理操作前均有确认弹窗且强调不可恢复；
3. 统计与清理逻辑统一处理“超过 1 小时未写入”的分片，尽量避免误删；
4. 建议在清理接口加审计注解，记录管理操作行为。

## 五、实施顺序建议

1. 后端先实现 `summary` 与两个 `cleanup` 接口，并本地测试统计与清理正确性；
2. 前端在 System.vue 中新增 Tab 与基本展示逻辑，接入 summary 接口；
3. 实现全局/按用户清理按钮与确认弹窗；
4. 最后联调，重点验证：
   - 正常上传流程不受影响；
   - 清理后 garbage 分片统计确实归零／减少；
   - 多管理员并发操作时无异常。
