# 企业文件管理器：备份与迁移方案（无停机完整版）

本文档为最终确认版本，覆盖在线（不中断）与维护模式导出、导入、作业管理、预检与定时备份策略。已确认的默认项：

- 在线导出默认冻结 GC 与管理员清理（对用户无感）
- 默认包含缩略图
- 不使用包加密/签名（保留扩展能力）
- 支持计划任务与保留策略（时间可配置）

## 1. 目标与保证

- 无损恢复：导入后系统恢复到“备份快照时刻”的状态（用户、文件、文件夹、历史版本、Blob、系统设置、审计）。
- 在线不中断：导出期间不阻断上传/下载/移动/删除，仅冻结后台清理任务（用户无感）。
- 强校验：manifest 记录表计数、Blob 引用数/总字节、缩略图数、差异清单；导入前后均做一致性检验。
- 安全可控：仅管理员可操作；导入需二次确认；导出到服务器路径受白名单限制。
- 计划任务：可配置 CRON、目标目录和保留策略。

## 2. 覆盖范围

- 必须包含：
  - 全库数据：users、folders、files、file_versions、blobs、system_config、user_logs 等。
  - Blob 内容：快照时刻 DB 引用到的所有 blob 哈希对应物理文件。
  - 回收站：默认包含（保持 deleted 状态与时间戳）。
- 可选（默认包含）：
  - thumbnails 缩略图（提高恢复后首屏体验）。
  - legacy 物理文件：若 DB 仍引用到非标准路径，检测到引用则纳入包内并在导入时归一化。
- 默认不包含（不影响用户已完成数据）：
  - 未引用的 Blob、分片 `{storage}/chunks/**`、临时 `{storage}/tmp/**`、运行日志、会话令牌、环境配置。

## 3. 备份包格式（zip）

- backup-{timestamp}.zip
  - manifest.json：mode(online|maintenance)、exportedAt、schemaVersion、appVersion、storagePath、表行数、R0 引用数/总字节、thumbnailCount、diff.missingBlobs[]、format(sql|json)。
  - db.sql（优先，mysqldump 可用）或 db.json（回退，服务内流式导出）。
  - blobs/：`{xx}/{yy}/{sha256}` 结构。
  - thumbnails/（默认包含）。
  - extra/（可选）：config 快照、legacy 文件等。

## 4. 导出一致性（不中断）

- DB 快照：
  - 优先 mysqldump：`--single-transaction --quick` 热备，不锁表；不可用则 REPEATABLE READ 长事务 + 流式 JSON。
- 冻结后台清理（导出窗口内，用户无感）：
  - `backup.gc.freeze=true`：Blob GC 定时和实现层检测后跳过。
  - `backup.admin-purge.freeze=true`：管理员排期清理定时和实现层检测后跳过。
- Blob 两阶段拷贝 + 终检补偿：
  - R0 = DISTINCT(file_versions.blob_hash) ∪ DISTINCT(files.file_hash)。
  - NIO 复制到 zip；复制完成后终检“R0 ⊆ 已复制集合”，缺失项定向重试；仍缺失则写入差异清单（正常应为空）。
- 收尾：写 manifest，释放冻结（含超时兜底）。

## 5. 维护模式导出（可选）

- 切换短时只读 → DB 快照 → Blob 拷贝 → 结束只读；适合超大体量或严格窗口。

## 6. 导入流程

- 预检：解包到临时目录；读取 manifest 与 db.sql|db.json；校验版本/结构/表计数/容量；可选校验和。
- 执行（二次确认）：
  - 切换维护/只读；可选创建当前系统快照。
  - `SET FOREIGN_KEY_CHECKS=0` → TRUNCATE ALL → 按 db.sql 或 db.json 重建（分批）。
  - 合并/覆盖 blobs（已存在跳过）；恢复 thumbnails（或批量重建）。
  - 后检验：校验“DB 引用 Blob 全存在”；失败保留维护态并输出差异清单。
  - 结束维护。

## 7. 后端接口

- 导出（下载）：GET `/api/admin/settings/backup/export?format=sql|json&includeThumbnails=true|false&mode=online|maintenance`
- 导出（保存到服务器）：POST `/api/admin/settings/backup/export-to-server`，body：`{ path, format, includeThumbnails, mode }`
- 预检（导入前）：POST `/api/admin/settings/backup/precheck`（multipart：`file=backup.zip`）
- 导入：POST `/api/admin/settings/backup/import`（multipart），字段：`file=backup.zip, mode=full, confirm=true, rebuildThumbnails=false`
- 维护/只读：POST `/api/admin/settings/maintenance { enabled: true|false }`
- 作业管理：
  - GET `/api/admin/settings/backup/jobs?page=&size=`
  - GET `/api/admin/settings/backup/jobs/{id}`
  - POST `/api/admin/settings/backup/jobs/{id}/cancel`

## 8. 系统设置键

- 冻结与维护：
  - `backup.gc.freeze`（BOOLEAN）
  - `backup.admin-purge.freeze`（BOOLEAN）
  - `system.maintenance.enabled`（BOOLEAN）
- 路径白名单：
  - `backup.whitelist.dirs=/var/backups/efm,/data/efm_backups`
- 导出控制：
  - `backup.concurrency.blobCopy=6`
  - `backup.io.throttle.bytesPerSec=`（空为不限）
  - `backup.zip.level=6`
- 定时备份：
  - `backup.schedule.enabled=true`
  - `backup.schedule.cron=0 0 2 * * ?`
  - `backup.schedule.dest=/var/backups/efm`
  - `backup.retention.days=14`

## 9. 安全与合规

- 管理员权限；导入二次确认；服务器导出路径白名单；Zip Slip 防护；限制单文件与总大小；（可扩展）加密/签名。

## 10. 性能与可靠性

- 全程流式；NIO 复制；并发与限速可配置；导入分批写入、禁外键/二级缓存；失败自动清理冻结；作业可取消/重试。
