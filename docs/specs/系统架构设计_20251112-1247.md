# 企业级文件管理系统 — 系统架构设计（v2.0）

> 更新时间：2025-11-12 12:47
> 适用范围：本仓库整体（backend、frontend、config、scripts、docker-compose）

本架构文档从系统视角梳理项目的关键决策、稳定结构与技术选型，便于新成员与评审人员快速理解系统。文档内容依据代码逐文件梳理归纳，覆盖后端 Spring Boot、前端 Vue、基础设施（MySQL、Redis、Nginx、Docker Compose）与运维要点。

## 一、约束条件
- 运行环境与语言
  - Java 17（Maven 编译 `maven-compiler-plugin:3.11.0`，后端 Spring Boot 3.2.0，artifact 版本 2.0.0）
  - Node.js 18（scripts/local_dev_setup.sh 中显式校验），Vue CLI 5 构建
  - 容器化：Docker + Docker Compose，单机/单集群容器编排
- 基础设施与外部依赖
  - 数据库：MySQL 8.0（docker 镜像 `mysql:8.0`），JPA/Hibernate，方言 MySQL8，DDL 自动更新
  - 缓存：Redis 7（镜像 `redis:7-alpine`），Spring Cache（TTL 600s 默认）
  - 反向代理：Nginx（前后端分发、限流/压缩、跨域头处理），对外端口默认 8888
- 鉴权与会话
  - 认证：JWT Bearer，无状态会话（SessionCreationPolicy.STATELESS）
  - 授权：基于 ROLE（ROLE_ADMIN/ROLE_USER），方法级 `@PreAuthorize` 与路径规则
  - 安全链：自定义 `JwtAuthenticationFilter` 前置于 `UsernamePasswordAuthenticationFilter`
  - CORS：允许任意源（开发/容器环境下便于联调）
- 存储与配额
  - 文件存储：本地文件系统（默认 `/tmp/cunchu` 或容器 `/app/storage`），需挂载持久卷
  - 用户配额：按用户维度统计 `quotaLimit/quotaUsed`，上传前校验与删除后释放
  - 上传限制：最大单文件/请求大小可由 `application.yml` 配置（示例 100MB/1GB）
  - 上传策略：支持“允许全部”或“后缀白名单”（系统设置持久化存储于 `system_config`）
- 部署拓扑
  - docker-compose: backend(8080) + frontend(80) + mysql(3306) + redis(6379) + nginx(80→对外8888)
  - 健康检查：后端 Actuator `/actuator/health`，Nginx `/health` 简单探活
- 代码与结构
  - 分层架构：Controller → Service → Repository → Entity
  - 横切关注：审计日志 AOP、指标（Micrometer/Actuator）、计划任务（回收/清理）

上述约束直接影响设计：无状态认证促使后端可横向扩展；本地文件存储要求挂载共享卷；容器化与健康检查定义了部署与运维边界；Redis TTL、上传策略与配额控制限定了性能与安全边界。

## 二、非功能性要求（NFR）
- 安全性
  - JWT + Spring Security；管理员接口强制 `ROLE_ADMIN`
  - 登录防护：错误累计后触发图形验证码（`CaptchaService` 带 key 一次性校验）
  - 密码强度与加密：BCrypt 存储；管理员改密需二次确认
  - CORS/Headers：Nginx 追加跨域响应头；后端允许所有来源（开发/容器内）
- 可用性与可靠性
  - Actuator 健康/指标；容器健康检查与重启策略
  - 定时任务：回收站到期清理（文件）、审计日志按保留期清理
  - 上传/下载：Nginx 关闭大文件缓冲；后端按流式处理与阈值
- 性能与扩展性
  - Redis 缓存与 TTL；JPA 分页检索与条件过滤（日志/文件）
  - 无状态后端便于横向扩展；前后端分离与静态资源加速
- 可观察性
  - 审计：统一记录成功/失败（API 失败有 AOP 兜底），导出 CSV/XLSX
  - 指标：Micrometer 计数器（成功/失败/清理条数），可对接 Prometheus/Grafana
  - 日志：后端按包粒度 DEBUG 可调，Nginx 访问日志标准化
- 可维护性与可测试性
  - 清晰分层，DTO 隔离；配置集中化（YAML + `system_config`）
  - 关键流程幂等（回收站清理/审计清理批量降级删除）

## 三、架构设计
- 分层组件
  - 表现层（Frontend）：Vue3 + Element Plus 单页应用（`/frontend/src`），通过 `/api` 代理访问后端
  - 接口层（Controller）：`AuthController`、`FileController`、`FolderController`、`Admin*Controller` 提供 REST API
  - 业务层（Service）：
    - 用户：`UserService`（登录/注册/资料/改密、Excel 导入导出）
    - 文件：`FileService`（上传、下载、缩略图、移动/重命名、回收站/管理员排期删除与到期清理、配额释放、上传后缀策略）
    - 文件夹：`FolderService`（增删改查、简单路径与移动）
    - 系统设置：`SystemSettingService`（布尔/整数/字符串与上传策略，持久化到 `system_config`）
    - 审计：`AuditLogService`（异步落库，失败降级不影响主流程）/`AuditLogQueryService`（条件过滤与分页/导出）
    - 验证码：`CaptchaService`（带 key 的一次性验证码与 PNG 绘制）
  - 数据层（Repository）：`UserRepository`、`FileRepository`、`FolderRepository`、`UserLogRepository`、`SystemConfigRepository`
  - 实体（Entity）：`User`、`File`、`Folder`、`UserLog`、`SystemConfig`（含审计与管理员回收流程的域字段）
  - 横切（Cross-Cutting）：
    - 安全：`SecurityConfig` + `JwtAuthenticationFilter` + `JwtUtils` + `UserDetailsService`
    - 审计切面：`ApiAuditAspect` 记录控制器成功/失败（可配置开关）
    - 计划任务：`RecyclePurgeScheduler`（管理员排期删除到期清理）、`AuditLogPurgeScheduler`（审计日志按天清理）
    - 指标：`AuditMetricsService`（Micrometer Counter）
- 关键流程示意
  - 登录：AuthController → UserService.authenticate → 生成 JWT（`JwtUtils`）→ 前端存储 Token → 路由守卫基于 `authorities/role`
  - 鉴权：每次请求 `JwtAuthenticationFilter` 解析 Token → `UserDetailsService` 装载权限 → `SecurityContext` 生效
  - 上传：Controller → `FileService.uploadFile`
    - 校验：配额、上传后缀策略（系统设置）
    - 落盘：用户独立目录、计算哈希、缩略图（受像素/大小阈值限制）
    - 记录：`files` 落库、用户配额累加、审计日志
  - 回收/清理：
    - 用户侧软删 → 可恢复、可彻底删除（ownerHidden true）
    - 管理员排期删除 → `adminDeleteScheduled/ExecuteTime/Reason` → 定时器到期物理清理
  - 审计：成功/失败统一收敛（AOP 兜底失败记录），导出 CSV/XLSX（大批量使用 SXSSFWorkbook 流式）

## 四、解决方案上下文图（黑盒视角）
```
[终端用户/管理员 浏览器]
          |
          v
       [Nginx]
    /静态  \ API
   v         v
[Vue SPA]  [Spring Boot API]
               | \ \\
               |  \ \-- Actuator (/actuator/*)
               |   \\
               v    v
           [MySQL] [Redis]
               |
           [文件系统卷 /app/storage]
```
说明：
- Nginx 将根路径/静态资源转发到前端容器，将 `/api/` 代理到后端；额外提供 `/health` 探活。
- 后端访问 MySQL/Redis；文件持久化在挂载卷；Actuator 供容器健康与运维观测。

## 五、解决方案容器图（部署/组件关系）
- Nginx（`filemanager-nginx`，端口 8888→80）
  - 反向代理前端与后端；添加 CORS 响应头；关闭下载缓冲
- 前端（`filemanager-frontend`，端口 8081→80）
  - Vue3 构建产物/开发服；通过 `/api` 调后端
- 后端（`filemanager-backend`，端口 8080）
  - Spring Boot 单体，暴露 REST + Actuator；无状态 JWT；计划任务与审计 AOP
- 数据库（`filemanager-mysql`，端口 3306）
  - 初始化脚本 `config/init.sql`；数据卷 `mysql_data`
- 缓存（`filemanager-redis`，端口 6379）
  - 缓存/会话相关键空间；可设置密码
- 存储卷
  - 文件存储 `/app/storage`（或 `/tmp/cunchu`），需持久化挂载

依赖关系：Nginx→前端/后端；后端→MySQL/Redis/存储卷。健康检查串联容器重启策略。

## 六、技术栈与版本信息（含选择理由）
- 后端
  - Spring Boot 3.2.0：成熟生态、Actuator 观测、与 Security/JPA 深度整合
  - Java 17：LTS 版本，语言/性能改进
  - Spring Security + JWT（jjwt 0.12.3）：无状态、易横向扩展
  - Spring Data JPA + Hibernate：声明式 ORM，便于维护与分页/过滤
  - MySQL Connector/J 8.0.33：与 MySQL 8 匹配
  - Redis（Spring Cache）：热点数据/验证码等缓存（TTL）
  - Hutool 5.8.25：通用工具集
  - Apache POI 5.2.4：Excel 导入导出（流式 SXSSF 支持大数据量）
  - Actuator + Micrometer：健康与指标
- 前端
  - Vue 3.3、Element Plus 2.4、Pinia 2.1、Vue Router 4.2、Axios 1.6：主流技术栈，生态完备
  - 构建：Vue CLI 5（生产与本地开发分别支持）
- 基础设施
  - Nginx（alpine）：静态资源与反代、压缩、跨域头
  - MySQL 8.0、Redis 7：稳定可靠，容器镜像官方维护
  - Docker Compose：一键编排，健康检查与依赖顺序

## 七、配置要点（示例）
- 后端 `backend/src/main/resources/application.yml`
  - `file.storage.path`、`jwt.secret/expiration`、`recycle.*`、`audit.*`、`spring.datasource.*`
- 容器 `config/backend/src/main/resources/application-docker.yml`
  - 容器内路径 `/app/storage`，日志路径 `/app/logs`
- 反向代理 `config/nginx/nginx.conf`
  - `/` 前端、`/api/` 后端、`/files/` 下载、`/health` 探活
- 前端 `frontend/src/utils/request.js`
  - 统一携带 `Authorization: Bearer <token>`，统一错误处理

## 八、数据模型（核心表）
- `users`：账号、状态、配额与审计引用
- `files`：文件元数据、删除标记、管理员排期删除字段、配额释放标记
- `folders`：层级关系、删除标记
- `user_logs`：审计日志（动作/资源/结果/IP/UA/耗时）
- `system_config`：系统设置（键/值/类型/描述/更新人）

## 九、演进与扩展建议
- 对象存储适配：抽象 `FileStorage` 接口，支持 S3/OSS/MinIO
- 鉴权/授权：细粒度权限（基于资源/策略），多租户隔离
- 审计/可观测：接入 Prometheus/Grafana、集中式日志（ELK/Opensearch）
- 性能：大文件分片上传/断点续传（已预留 chunk 配置项），热点目录缓存
- 可用性：读写分离/连接池/索引优化，幂等接口与重试策略
