# 日志审计实现方案（2025-11-11 12:40）

本方案用于在“对话上下文被清空”的情况下，仍可无损地继续实现与对接日志审计模块。包含目标、范围、数据模型、采集策略、查询与导出、定时清理、配置、索引、前端改造、验收与里程碑，以及详细的落地步骤与文件路径。

— 本文档为设计与落地说明，不直接修改现有代码。按本文逐步实现即可。

## 1. 背景与目标
- 背景：README 目标包含“操作日志：完整的用户操作记录”，当前仅存在 `UserLog` 实体，尚未接入采集与查询。
- 目标：对所有经由后端的用户/管理员操作进行统一记录（谁、何时、何地、对何资源、做了什么、耗时、结果、失败原因），支持分类检索、时间排序、关键词搜索、时间范围过滤与导出；支持保留期与定时清理。

## 2. 范围与覆盖
- 覆盖动作（不限于）：
  - 认证：LOGIN（成功/失败）、ADMIN_LOGIN（成功/失败）、LOGOUT
  - 文件：UPLOAD、DOWNLOAD、DELETE（软删）、RESTORE、COPY、MOVE、RENAME
  - 回收站（用户）：RECYCLE_REMOVE（从用户回收站移除）、RECYCLE_EMPTY（仅隐藏）
  - 回收站（管理员）：ADMIN_SCHEDULE_DELETE（排期删除）、ADMIN_RESTORE（恢复到管理员网盘）、ADMIN_PURGE_EXPIRED（到期清理）
  - 用户资料/密码：UPDATE_PROFILE、CHANGE_PASSWORD
  - 文件夹：CREATE_FOLDER、DELETE_FOLDER、RENAME_FOLDER、MOVE_FOLDER
- 资源分类：FILE / FOLDER / USER（可扩展 SYSTEM/CONFIG）
- 不可覆盖的天然限制：不经后端的直链访问（如对象存储直链）、DB/文件系统人工操作等。

## 3. 数据模型
- 复用：backend/src/main/java/com/filemanager/entity/UserLog.java
- 关键字段：
  - user（操作者）、actionType、actionDescription、resourceType、resourceId、resourceName
  - ipAddress、userAgent、status（SUCCESS/FAILED）、errorMessage（≤1000）、executionTime（ms）、createTime
- 建议新增/扩展常量：ADMIN_SCHEDULE_DELETE、ADMIN_RESTORE、ADMIN_PURGE_EXPIRED、RECYCLE_REMOVE、RECYCLE_EMPTY、ADMIN_LOGIN

## 4. 采集策略（零漏记）
- 显式埋点（服务层）：在 UserService/FileService/FolderService/管理员回收站逻辑中记录成功/失败，包含业务上下文（资源名、理由、配额变化等）。
- 控制器 AOP 兜底：对所有 `@RequestMapping` 入口切面，记录请求元数据与结果；若该请求无显式埋点，则按 `actionType=OTHER` 或 `API_{HTTP_METHOD}` 归类，避免漏记。
- 安全/调度钩子：
  - 登录：UserService 内记录；可选扩展 AuthenticationSuccess/FailureHandler。
  - 定时任务：到期清理在任务处记录统计（成功/失败数量）。
- 敏感信息处理：不记录密码/令牌/文件内容；错误信息截断。

## 5. 写入服务与请求信息
- 新增：AuditLogService（@Service @Async）
  - 方法签名（建议）：
    - `void logSuccess(Long userId, String actionType, String resourceType, Long resourceId, String resourceName, String description, Long execMs)`
    - `void logFailure(Long userId, String actionType, String resourceType, Long resourceId, String resourceName, String description, String errorMessage, Long execMs)`
  - 统一补齐：ipAddress、userAgent、createTime
- 新增：RequestInfoProvider（从 RequestContextHolder 获取 HttpServletRequest）
  - `String getClientIp()`：优先 X-Forwarded-For / X-Real-IP
  - `String getUserAgent()`
- 说明：已启用 `@EnableAsync`，异步写入不会阻塞业务链路。

## 6. 查询服务与过滤
- 新增：UserLogRepository（JPA）
- 新增：AuditLogQueryService（JPA Specification/Criteria）
  - 过滤参数：
    - actions（多选，逗号分隔）、resourceTypes（多选）、status
    - keyword（对 username/displayName 模糊匹配，Join users）
    - from / to（ISO 时间/日期）
    - sort=createTime，order=asc|desc（默认 desc）
  - 返回：Page<UserLogDTO>
- DTO：UserLogDTO（id,userId,username,displayName,actionType,resourceType,resourceId,resourceName,status,errorMessage,ipAddress,userAgent,executionTime,createTime）

## 7. 管理控制器接口
- 新增：AdminLogController（路径 `/api/admin/logs`）
  - GET `/api/admin/logs`（分页列表）
    - 参数：page,size,actions,resourceTypes,status,keyword,from,to,sort,order
    - 返回：分页 UserLogDTO
  - GET `/api/admin/logs/export`（导出 CSV/XLSX）
    - 参数同上，新增 `format=csv|xlsx`
    - 限制：`audit.export.max-rows`（默认≤50000），超限报错提示
  - GET `/api/admin/logs/actions`（可选）
    - 返回系统内已知动作枚举，便于前端渲染过滤器
  - 权限：`ROLE_ADMIN`

## 8. 导出实现
- CSV：流式 `text/csv`，UTF-8 BOM 可选；逐行写出，低内存。
- XLSX：Apache POI `SXSSFWorkbook` 流式；大数据导出内存占用低。
- 文件名：`user-logs_{yyyyMMdd_HHmmss}.{csv|xlsx}`
- 列：时间、用户名、昵称、动作、资源类型/ID/名称、结果、耗时、IP、UA、失败原因。

## 9. 定时清理与保留期
- 配置：`audit.retention-days: 180`（默认半年）
- 新增：AuditLogPurgeScheduler（@Scheduled）
  - `audit.purge.cron: 0 0 3 * * ?`（每日3点）
  - 分页批处理删除过期数据（每批固定条数），避免长事务。

## 10. 配置项（application.yml）
```yaml
audit:
  enabled: true
  retention-days: 180
  export:
    max-rows: 50000
  purge:
    cron: "0 0 3 * * ?"
```

## 11. 数据库索引与迁移
- 建议索引：
  - `user_logs(user_id, create_time)`
  - `user_logs(action_type, create_time)`
  - `user_logs(resource_type, resource_id)`
  - `user_logs(status, create_time)`
- 迁移建议：生产环境使用 Flyway/Liquibase 管理 DDL，避免 `ddl-auto:update` 带来的不确定性。

## 12. 前端改造（管理员）
- 新增“操作日志”页面：
  - 过滤器：动作（多选）、资源（多选）、状态（多选）、时间范围、关键词（用户名/昵称）
  - 列表：按时间倒序展示（可切换升序），分页
  - 导出：基于当前过滤条件导出 CSV/XLSX（提示最大行数）
  - 详情：弹窗查看 `actionDescription` 与 `errorMessage`

## 13. 安全与合规
- 不记录密码、Token、文件内容。
- 错误信息截断（≤1000）。
- 仅管理员可访问查询/导出接口。
- 可选：`audit.enabled=false` 时关闭审计（不建议在生产关闭）。

## 14. 验收与测试
- 用例：
  - 登录成功/失败；上传/下载/删除/恢复/复制/移动/重命名；回收站移除/清空；管理员排期/恢复/清理。
  - 检索：动作/资源/状态/时间/关键词组合过滤；时间排序。
  - 导出：对不同过滤条件导出 CSV/XLSX，核对列与数据；验证超限提示。
  - 清理：构造过期数据，验证定时清理。
- 指标：在10万级日志下，分页查询响应可接受（依赖索引）；导出在限量内稳定。

## 18. 风险与缓解
- 漏记风险：通过“服务层显式埋点 + AOP 兜底”组合消除。
- 性能风险：大表分页与导出通过索引与流式处理缓解；导出设置最大行数。
- 合规风险：敏感数据不入库；错误信息截断；仅管理员可查询导出。

## 19. 示例：描述模板（片段）
